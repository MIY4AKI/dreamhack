# Dreamhack Assembly Language — 컴퓨터 아키텍처 기초

## 1. 강의 목표

이 강의는 프로그램이 CPU에서 실행되는 큰 흐름과 x86-64의 핵심 레지스터를 이해하기 위한 배경 강의다. 세부 회로를 외우는 것이 목적이 아니라, 이후 어셈블리 코드에서 등장하는 레지스터·주소·플래그가 어떤 역할을 하는지 연결하는 것이 중요하다.

핵심 키워드:

- 컴퓨터 구조(Computer Architecture)
- 명령어 집합 구조(Instruction Set Architecture, ISA)
- 폰 노이만 구조
- x86-64와 64비트 아키텍처
- 범용·세그먼트·명령어 포인터·플래그 레지스터

---

## 2. 컴퓨터 구조, ISA, 마이크로아키텍처

### 컴퓨터 구조

컴퓨터 구조는 CPU, 메모리, 입출력 장치 등의 구성 요소가 어떻게 설계되고 상호작용하는지를 다루는 큰 개념이다. 프로그램 관점에서는 “작성한 코드가 어떤 단계를 거쳐 기계 수준에서 실행되는가”를 설명하는 설계라고 볼 수 있다.

### ISA

ISA는 CPU가 이해하는 명령어, 레지스터, 데이터 형식, 메모리 접근 방식 등을 정의한 소프트웨어와 하드웨어 사이의 규약이다.

| 구분 | 질문 | 예시 |
|---|---|---|
| 컴퓨터 구조 | 컴퓨터 전체를 어떻게 구성할 것인가? | 폰 노이만·하버드 구조, 메모리 계층 |
| ISA | CPU가 어떤 명령을 어떤 규칙으로 실행하는가? | x86-64, ARM, MIPS, AVR |
| 마이크로아키텍처 | ISA를 실제 회로로 어떻게 빠르고 효율적으로 구현하는가? | 파이프라인, 캐시, 분기 예측, 비순차 실행 |

동일한 x86-64 ISA를 구현하더라도 제조사와 세대에 따라 내부 파이프라인과 캐시 구조가 다를 수 있다. 반대로 ISA가 다르면 같은 바이트열도 전혀 다른 명령으로 해석될 수 있다.

---

## 3. 폰 노이만 구조

폰 노이만 구조는 연산·제어·저장 기능을 중심으로 컴퓨터를 구성하며, 프로그램의 명령어와 데이터를 같은 기억장치에 저장하는 저장 프로그램 방식을 사용한다.

```text
          주소·데이터·제어 버스
CPU  <---------------------------->  메모리
 |                                     |
 +-----------> 입출력 장치 <-----------+
```

### CPU의 주요 구성

- **ALU(Arithmetic Logic Unit)**: 덧셈, 뺄셈, AND, OR 같은 산술·논리 연산을 수행한다.
- **제어장치(Control Unit)**: 명령어를 가져오고 해석하며 각 구성 요소의 동작을 제어한다.
- **레지스터(Register)**: 연산 직전에 필요한 값, 주소, 상태를 CPU 내부에 매우 빠르게 보관한다.

CPU는 대체로 다음 흐름을 반복한다.

1. 명령어 포인터가 가리키는 메모리에서 명령어를 가져온다(Fetch).
2. 명령어의 의미와 피연산자를 해석한다(Decode).
3. ALU, 레지스터, 메모리 등을 이용해 실행한다(Execute).
4. 결과를 레지스터나 메모리에 기록하고 다음 명령으로 이동한다.

### 기억장치

- **주기억장치**: 프로그램 실행 중 필요한 데이터를 임시 저장한다. 대표적으로 RAM이 있다.
- **보조기억장치**: 프로그램과 파일을 장기간 보관한다. HDD와 SSD가 대표적이다.

레지스터와 캐시가 필요한 이유는 CPU 연산 속도와 RAM 접근 속도의 차이를 줄이기 위해서다. 매 연산마다 느린 주기억장치만 기다리면 CPU가 대부분의 시간을 대기에 소비하게 된다.

### 버스

- 데이터 버스: 실제 데이터를 전달한다.
- 주소 버스: 읽거나 쓸 위치를 지정한다.
- 제어 버스: 읽기/쓰기, 인터럽트 등의 제어 신호를 전달한다.

## 4. CISC와 RISC

| 구분 | CISC | RISC |
|---|---|---|
| 명령어 성격 | 복잡하고 종류가 많으며 길이가 가변적일 수 있음 | 단순하고 종류가 비교적 적으며 길이가 일정한 경우가 많음 |
| 장점 | 한 명령이 많은 일을 하므로 코드 밀도를 높이기 쉬움 | 디코딩과 파이프라인 구성이 단순해지기 쉬움 |
| 단점 | 명령 해석과 구현이 복잡해질 수 있음 | 같은 작업에 더 많은 명령이 필요할 수 있음 |
| 대표 계열 | x86, x86-64 | ARM, MIPS, RISC-V |

현대 CPU는 내부 구현에서 두 철학을 섞어 사용하기도 하므로 “x86은 언제나 느리고 ARM은 언제나 빠르다”처럼 단순화하면 안 된다. 강의에서 중요한 점은 **분석 대상의 ISA에 맞는 어셈블리어를 읽어야 한다**는 것이다.

## 5. x86-64 아키텍처

x86-64는 32비트 x86(IA-32)을 64비트로 확장하면서 기존 x86 소프트웨어와의 호환성을 유지한 ISA다. AMD64, Intel 64, x64라는 이름도 같은 계열을 가리킨다.

### n비트 아키텍처의 의미

“64비트”는 보통 CPU가 자연스럽게 처리하는 워드 크기, 범용 레지스터 크기, 주소 계산 능력 등을 설명한다. 주소가 64비트라고 해서 실제 하드웨어가 항상 2⁶⁴바이트 전체를 구현하는 것은 아니며, CPU와 운영체제가 지원하는 유효 주소 비트 수에는 현실적인 제한이 있다.

32비트 주소 공간은 이론상 `2^32 = 4 GiB`, 64비트 주소 공간은 이론상 `2^64 = 16 EiB`다.

> x86 어셈블리 문법에서 `WORD`는 역사적 호환성 때문에 16비트를 뜻한다. 32비트는 `DWORD`, 64비트는 `QWORD`다. CPU의 자연 워드 크기라는 일반 개념과 문법의 자료형 이름을 구분해야 한다.

---

## 6. x86-64 레지스터

### 범용 레지스터

범용 레지스터는 정수 연산, 주소 계산, 인자 전달 등에 사용한다. 이름에 따른 전통적 주 용도가 있지만 호출 규약과 명령어 제약을 지키는 범위에서 다양한 목적으로 사용할 수 있다.

| 레지스터 | 전통적 의미·자주 보는 용도 |
|---|---|
| `rax` | Accumulator, 함수 반환값, 곱셈·나눗셈의 암시적 피연산자 |
| `rbx` | Base, 일반 보관용; System V에서는 callee-saved |
| `rcx` | Counter, 반복·시프트 횟수; System V 함수의 4번째 인자 |
| `rdx` | Data, 곱셈·나눗셈 상위 결과; System V 함수의 3번째 인자 |
| `rsi` | Source Index, 복사 원본; System V 함수의 2번째 인자 |
| `rdi` | Destination Index, 복사 목적지; System V 함수의 1번째 인자 |
| `rsp` | 현재 스택의 최상단을 가리키는 Stack Pointer |
| `rbp` | 전통적인 Stack Frame/Base Pointer |
| `r8`~`r15` | x86-64에서 추가된 범용 레지스터 |

### 하위 레지스터 호환

한 물리 레지스터의 일부를 크기별 이름으로 접근할 수 있다.

| 크기 | RAX 계열 | RBX 계열 | RCX 계열 | RDX 계열 |
|---:|---|---|---|---|
| 64비트 | `rax` | `rbx` | `rcx` | `rdx` |
| 하위 32비트 | `eax` | `ebx` | `ecx` | `edx` |
| 하위 16비트 | `ax` | `bx` | `cx` | `dx` |
| 상위 8비트 | `ah` | `bh` | `ch` | `dh` |
| 하위 8비트 | `al` | `bl` | `cl` | `dl` |

중요한 x86-64 규칙:

- `eax`처럼 32비트 하위 레지스터에 값을 쓰면 대응하는 상위 32비트가 0으로 지워진다.
- `ax`, `al` 등에 쓰는 경우에는 나머지 상위 비트가 자동으로 모두 지워지지 않는다.
- 서로 다른 크기의 레지스터를 사용할 때 값의 잘림과 부호/제로 확장을 의식해야 한다.

### 명령어 포인터

`rip`는 CPU가 다음에 실행할 명령어의 위치를 나타내는 64비트 명령어 포인터다. `call`, `ret`, `jmp`, 조건 분기 등이 실행되면 `rip`의 흐름이 바뀐다. x86-64에서는 `[rip + offset]` 형태의 RIP-relative 주소 지정이 자주 등장한다.

### 세그먼트 레지스터

`cs`, `ss`, `ds`, `es`, `fs`, `gs`가 있다. 과거 16비트 x86에서는 세그먼트와 오프셋을 조합해 더 넓은 주소 공간에 접근하는 데 핵심적으로 사용됐다.

현대 64비트 모드에서는 전통적인 세그먼테이션 대부분이 평탄화되어 `cs`, `ds`, `ss`, `es`의 주소 계산 역할이 크게 줄었다. 실무에서는 `fs`와 `gs`의 베이스가 스레드 로컬 저장소(TLS)나 운영체제별 특수 구조 접근에 사용되는 경우가 특히 중요하다.

## 7. RFLAGS

`RFLAGS`는 연산 결과와 CPU 제어 상태를 비트별로 보관한다. 조건 분기 명령은 주로 다음 상태 플래그를 읽는다.

| 플래그 | 의미 | 대표 상황 |
|---|---|---|
| `CF`(Carry) | 부호 없는 연산에서 자리올림/빌림 발생 | unsigned 범위 초과, `jb`/`jae` 판단 |
| `ZF`(Zero) | 결과가 0 | 두 값이 같음, 0 검사 |
| `SF`(Sign) | 결과의 최상위 비트가 1 | 결과가 음수로 해석될 가능성 |
| `OF`(Overflow) | 부호 있는 연산의 범위 초과 | 큰 양수+양수→음수처럼 부호가 비정상 변화 |

예를 들어 `cmp a, b`는 내부적으로 `a - b`를 계산하되 결과 자체는 버리고 플래그만 바꾼다.

```asm
mov eax, 3
mov ebx, 5
cmp eax, ebx     ; 3 - 5: ZF=0, signed 비교에서 3 < 5
jl  less_label
```

`CF`는 부호 없는 비교, `SF`와 `OF` 조합은 부호 있는 비교에 중요하다. 따라서 같은 비트열을 signed와 unsigned 중 어느 관점으로 비교하는지에 따라 사용할 분기 명령이 달라진다.

---

## 8. 보안 학습과의 연결

- 리버스 엔지니어링에서는 `rip`와 분기 명령을 따라 프로그램의 제어 흐름을 복원한다.
- 시스템 해킹에서는 `rsp`, `rbp`, 반환 주소를 이해해야 스택 손상 취약점을 분석할 수 있다.
- 레지스터 호출 규약을 알아야 함수에 전달되는 인자와 반환값을 찾을 수 있다.
- `RFLAGS`를 이해해야 조건 검사 우회나 검증 로직을 정확히 읽을 수 있다.
- 서로 다른 ISA의 바이너리는 명령어 인코딩과 호출 규약이 다르므로 분석 도구의 아키텍처 설정을 확인해야 한다.

## 핵심 체크

- ISA와 마이크로아키텍처는 같은 개념이 아니다.
- `rip`는 실행 흐름, `rsp`는 스택의 현재 위치를 추적하는 핵심 레지스터다.
- `eax`에 쓰면 `rax`의 상위 32비트가 0이 된다.
- `ZF`만으로 모든 대소 비교를 해결할 수 없으며 signed/unsigned 구분이 필요하다.
- 문법의 `WORD`는 x86에서 16비트다.
