# Dreamhack Assembly Language — Exercise: GDB

## 1. 실습 목표

이 강의는 GDB 워게임 바이너리에서 다음 두 작업을 수행하며 앞 강의의 명령을 실제 분석 흐름으로 연결한다.

1. 특정 함수의 **반환값**을 알아낸다.
2. 조건 분기 직전 레지스터 값을 바꿔 평소 실행되지 않는 경로를 실행시킨다.

정답 문자열을 외우는 실습이 아니라, 반환 시점과 분기 조건을 찾아내는 절차를 익히는 실습이다. 바이너리 버전이 바뀌면 주소와 실제 값은 달라질 수 있다.

---

## 2. 시작 전 확인

```bash
gdb ./main
```

GDB가 파일을 읽었다는 메시지를 확인한다. `No such file or directory`라면 현재 디렉터리와 바이너리 경로를 확인한다.

기본 점검:

```gdb
info files
info functions flag
disassemble main
```

심볼이 남아 있다면 `flag_1`, `flag_2` 같은 함수 이름으로 바로 중단점을 걸 수 있다. 심볼이 없다면 문자열 참조, 호출 대상, 디스어셈블 결과를 이용해 주소를 찾아야 한다.

---

## 3. 반환값 찾기 — 방법 1: `break` + `finish`

System V AMD64 호출 규약에서 일반적인 정수·포인터 반환값은 `rax`에 저장된다. 따라서 목표 함수가 반환한 직후 `rax`를 확인하면 된다.

```gdb
break flag_1
run
finish
info registers rax
```

흐름:

1. `flag_1` 진입점에 중단점을 설정한다.
2. 프로그램을 실행해 함수 안에서 멈춘다.
3. `finish`로 현재 함수가 끝날 때까지 실행한다.
4. 호출자로 복귀한 직후 `rax`를 확인한다.

`finish`는 “현재 함수가 반환할 때까지 실행”하는 명령이므로 함수 규모가 크거나 내부 구현이 중요하지 않을 때 가장 간단하다.

주의:

- 반환 타입이 큰 구조체, 부동소수점, 벡터라면 다른 레지스터나 숨은 포인터가 사용될 수 있다.
- 반환 직후 다른 명령이 `rax`를 덮어쓰기 전에 확인해야 한다.

---

## 4. 반환값 찾기 — 방법 2: `backtrace` + 반환 지점 중단점

`finish` 대신 호출자가 어디에서 목표 함수를 불렀는지 직접 찾을 수 있다.

```gdb
break flag_1
run
backtrace
```

백트레이스에서 호출자 프레임의 주소를 확인한 뒤 주변을 디스어셈블한다.

```gdb
disassemble main
# 또는
disassemble <호출자주소-여유>, <호출자주소+여유>
```

다음 형태를 찾는다.

```asm
call flag_1
next_instruction:     ; call 바로 다음이 반환 후 실행 지점
```

그 주소에 중단점을 걸고 계속 실행한다.

```gdb
break *next_instruction
continue
info registers rax
```

이 방법이 주는 이해:

- `call`은 다음 명령의 주소를 스택에 반환 주소로 저장한다.
- 피호출자가 `ret`하면 그 반환 주소가 `rip`로 복원된다.
- 호출 직후 `rax`에는 함수가 돌려준 값이 있다.

---

## 5. 조건 분기 우회 — 레지스터 변경

두 번째 목표는 특정 비교 또는 `test` 명령 직전에 레지스터 값을 원하는 조건으로 바꾸는 것이다.

전형적인 코드:

```asm
test al, al
jne  skip_flag_2
call flag_2
```

`test al, al`은 `al & al`의 결과로 플래그를 바꾼다. `al == 0`이면 ZF가 1이 되고 `jne`가 실행되지 않아 다음 경로로 진행한다.

디버깅 절차:

```gdb
break *<test의 주소>
run
info registers rax
set $rax = 0
info registers rax
continue
```

핵심은 분기 명령 자체를 무작정 건너뛰는 것이 아니라, **분기가 어떤 플래그를 읽고 그 플래그가 어떤 직전 연산에서 만들어지는지** 이해하는 것이다.

### 다른 접근

명령어 한 줄씩 확인할 수 있다.

```gdb
set $rax = 0
si                  # test 실행
info registers eflags
si                  # 조건 분기 실행
```

pwndbg의 context는 어떤 분기가 선택될지 화살표와 함께 보여줄 수 있다.

## 6. 사용한 명령어 정리

| 목적 | 명령 |
|---|---|
| 함수 진입 중단 | `b flag_1` |
| 실행 | `r` |
| 함수 반환까지 실행 | `finish` |
| 호출 경로 | `bt` |
| 호출자 코드 확인 | `disass main` |
| 주소 중단점 | `b *0x...` |
| 실행 재개 | `c` |
| 반환값 확인 | `i r rax` 또는 `p/x $rax` |
| 레지스터 변조 | `set $rax = 0` |
| 한 명령 추적 | `ni`, `si` |

## 7. 실습에서 얻어야 할 개념

- 함수 이름에 중단점을 걸 수 있으면 시작점 찾기가 쉬워진다.
- `finish`는 반환 직후의 상태를 관찰하는 가장 직접적인 방법이다.
- `backtrace`와 `disassemble`을 조합하면 호출 지점과 반환 지점을 직접 복원할 수 있다.
- x86-64 System V에서 일반 정수 반환값은 `rax`에 있다.
- GDB의 `set`은 단순 관찰을 넘어 대상 프로세스의 상태와 실행 경로를 바꿀 수 있다.
- 주소와 플래그 값은 실행 환경과 바이너리 빌드에 따라 달라지므로 원리를 기준으로 분석한다.
