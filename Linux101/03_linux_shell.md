## 1. 리눅스를 배우는 이유

리눅스는 개인용 데스크톱에서는 Windows나 macOS보다 낯설 수 있지만, 서버와 보안 학습에서는 자주 만나는 환경입니다. Unix 계열 운영체제의 공통된 사용 방식을 배우는 데에도 도움이 됩니다.

강의가 제시한 점유율은 **2024년의 자료**입니다. 데스크톱은 2024년 5월 기준 Windows 73.9%, macOS 14.91%, Linux 3.77%, 서버는 2024년 기준 Linux 기반 62.7%라는 수치로 학습 필요성을 설명합니다. 이는 강의의 역사적 예시이며, 현재 점유율로 해석하지 않습니다.

- 리눅스는 Linus Torvalds가 개발을 시작한 Unix-like 운영체제이며, 현재는 많은 기여자가 개발에 참여합니다.
- 오픈 소스라는 특성으로 코드를 확인하고 변경할 수 있습니다.
- 같은 리눅스 기반이라도 패키지 구성, 기능, 사용자 인터페이스가 다른 **배포판**이 있습니다.
- 대표적인 배포판: Ubuntu, CentOS, Debian, Fedora, Arch Linux.

강의의 계통도는 Unix 계열 운영체제의 관계를 보여줍니다. 여기서 중요한 것은 “리눅스 사용 경험이 다른 Unix 계열 환경을 이해하는 데 연결된다”는 점이지, 모든 운영체제가 동일하게 동작한다는 뜻은 아닙니다.

## 2. 셸과 터미널

**셸(Shell)**은 사용자가 운영체제와 상호작용하는 인터페이스를 제공하는 소프트웨어입니다. 명령을 받아 해석하고, 프로그램 실행 등의 작업을 수행합니다. 운영체제의 핵심인 커널을 감싸는 ‘껍질’이라는 비유에서 이름이 나왔습니다.

강의는 운영체제를 유저 레벨과 커널 레벨로 나누어 설명합니다. 일반 사용자는 커널 내부를 직접 조작하는 대신 셸과 프로그램을 통해 운영체제 기능을 사용합니다. 데스크톱의 그래픽 환경도 넓은 의미의 셸이며, 텍스트 명령을 입력하는 CLI 셸도 셸입니다.

**터미널(Terminal)**은 CLI 셸을 사용하는 입출력 창을 제공하는 프로그램입니다. Ubuntu Desktop에서 터미널을 열면 그 안에서 보통 Bash가 실행됩니다.

- 터미널: 창, 키보드 입력, 텍스트 출력 등의 입출력 환경.
- 셸: 입력한 명령을 해석하는 프로그램.
- 따라서 터미널과 셸은 같은 개념이 아닙니다. 하나의 터미널에서 서로 다른 셸을 실행할 수 있습니다.
- 강의 실습은 Bash를 기준으로 합니다. 다른 셸의 모든 차이를 암기하기보다 이름과 특징을 구분하면 충분합니다.

## 3. GUI와 CLI

### GUI 셸

- Graphical User Interface를 사용합니다.
- 바탕화면, 아이콘, 검색창 같은 요소를 보고 직관적으로 조작할 수 있습니다.
- 그래픽 처리에 자원이 필요하고, 복잡한 작업을 정밀하게 조합하는 데에는 한계가 있을 수 있습니다.

### CLI 셸

- Command-Line Interface를 사용합니다.
- Windows의 CMD 같은 명령 프롬프트, 터미널 안에서 사용하는 Unix 셸 등이 예입니다.
- 명령과 문법을 익혀야 해서 처음에는 비직관적으로 느껴질 수 있습니다.
- 반복 작업, 세부 설정, 여러 명령의 연결처럼 정밀한 작업에 유리합니다.

강의는 GUI를 Scratch의 블록 프로그래밍, CLI를 C 언어에 비유합니다. 보이는 기능을 조작하는 방식과 문법을 직접 작성하는 방식의 차이를 이해하기 위한 비유입니다. 실제 속도는 수행하는 작업과 프로그램에 따라 달라집니다.

Ubuntu Desktop처럼 GUI가 있는 배포판에서도 리눅스 학습은 주로 CLI로 진행합니다. 리눅스의 많은 관리 기능과 세부 작업을 명령으로 다루기 편리하기 때문입니다.

## 4. 대표적인 셸

### sh — Bourne Shell

Unix Version 7의 기본 셸로 등장하여 Thompson Shell과 PWB Shell을 대체했습니다. 기존 기본 셸의 실행 이름이 `sh`였기 때문에 이 이름을 이어받았습니다.

지원하는 핵심 기능:

- 프로그램 실행.
- 기본적인 입력과 출력.
- 환경 변수 설정.
- `if`, `while` 등의 문법을 이용한 셸 프로그래밍.

터미널에서 `sh`를 입력하면 해당 시스템의 `sh`를 실행합니다. 오늘날 `/bin/sh`가 역사적인 Bourne Shell 자체가 아니라 Dash 등 호환 셸을 가리키는 경우도 있으므로 이름만 보고 구현을 단정하지 않습니다.

### bash — Bourne-Again Shell

Brian Fox가 작성한 GNU 셸로, sh를 대체하고 확장하는 목적에서 개발되었습니다. 리눅스 학습 자료에서 매우 흔하며, 강의의 기본 실습 셸입니다. macOS에서도 과거 기본 셸로 사용되었고 여러 환경에 이식되었습니다.

sh 기능에 더해 강의에서 강조하는 기능:

- **명령 히스토리**: 이전에 실행한 명령을 기록하고 다시 사용할 수 있습니다.
- **Tab 자동 완성**: 명령이나 경로의 일부를 입력한 뒤 Tab으로 완성하거나 후보를 확인할 수 있습니다. 상황에 따라 Tab 한 번으로 완성되고, 두 번 누르면 후보 목록이 표시됩니다.
- **시작·종료 파일**: 셸을 시작하거나 종료할 때 설정 파일을 읽어 환경을 구성할 수 있습니다.

### ash / dash

- ash: Almquist Shell.
- dash: Debian Almquist Shell.
- Bash보다 작고 가벼우며 라이브러리 의존성이 적은 셸입니다.
- 강의는 FreeBSD, NetBSD, 일부 리눅스 배포판과 같은 환경을 예로 듭니다.
- 작은 저장 공간의 환경, 관리용 셸, `/bin/sh` 대체 등에 사용됩니다. 강의의 플로피 디스크 예시는 경량성이 필요한 역사적 상황을 설명합니다.

### zsh — Z Shell

Paul Falstad가 처음 작성한 셸입니다. Bourne Shell을 기반으로 Bash, ksh 등 여러 셸의 장점을 확장했으며, 사용자 정의와 설치가 비교적 편리하다는 특징을 소개합니다. 강의는 macOS의 기본 셸로 Zsh를 제시합니다.

## 5. Bash 시작·종료 파일

강의가 강조하는 차이는 **로그인해서 시작한 셸**과 **이미 열린 셸에서 다시 실행한 셸**의 설정 파일이 다를 수 있다는 것입니다.

### 로그인 셸

SSH 접속 등의 로그인 상황에서는 다음 순서를 이해합니다.

1. `/etc/profile`을 읽습니다.
2. `~/.bash_profile`, `~/.bash_login`, `~/.profile`을 순서대로 찾아 **처음으로 존재하고 읽을 수 있는 파일 하나**를 읽습니다.
3. 로그인 셸이 종료될 때 `~/.bash_logout`이 있으면 읽습니다.

### 대화형 비로그인 셸

터미널에서 `bash`를 다시 실행하는 상황의 대표적인 사용자 설정 파일은 `~/.bashrc`입니다. Ubuntu/Debian 환경에서는 시스템 설정 파일인 `/etc/bash.bashrc`도 사용합니다.

> 보충: 강의의 “Bash 실행 시 시작 파일”은 대화형 사용을 중심으로 한 설명입니다. 비대화형 스크립트 실행은 같은 규칙으로 단정하면 안 됩니다. 로그인 설정 파일 세 개도 모두 실행되는 것이 아니라 첫 번째 읽을 수 있는 파일을 선택합니다. [Bash 매뉴얼의 INVOCATION](https://man7.org/linux/man-pages/man1/bash.1.html)
