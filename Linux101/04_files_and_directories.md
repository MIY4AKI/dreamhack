## 1. 파일과 디렉터리의 의미

**파일(File)**은 의미 있는 정보를 모은 논리적 단위입니다. 텍스트, 실행 파일, 이미지처럼 용도에 따라 여러 종류가 있습니다. 보통 `이름.확장자` 형태로 이름을 붙이지만 리눅스에서 확장자는 필수가 아닙니다.

- `.sh`, `.log` 등의 확장자는 사람이 종류를 구분하기 쉽게 만드는 관례입니다.
- 파일 형식을 식별하는 도구나 프로그램은 확장자 외에도 내부 데이터를 확인할 수 있습니다.
- 파일 앞부분의 특정 바이트로 형식을 구분할 때 그 값을 **매직 넘버(Magic Number)** 또는 **파일 시그니처(File Signature)**라고 합니다.
- 확장자를 바꾼다고 파일 데이터의 형식까지 바뀌지는 않습니다.
- 모든 형식에 고정된 시그니처가 있는 것은 아니며, 확장자를 활용하는 프로그램도 있습니다. “리눅스는 언제나 확장자를 무시한다”는 뜻으로 일반화하지 않습니다.

**디렉터리(Directory)**는 파일과 다른 디렉터리를 분류하는 네임스페이스입니다. Windows에서 말하는 폴더와 대응합니다.

- 안에 들어 있는 디렉터리: 하위 디렉터리(child/subdirectory).
- 자신을 포함하는 디렉터리: 상위 디렉터리(parent directory).
- 디렉터리와 파일은 보통 트리 구조를 이룹니다.
- 리눅스는 디렉터리도 특수한 종류의 파일로 관리합니다. 셸 명령은 작업에 따라 일반 파일과 디렉터리를 구별합니다.

리눅스에서 하드웨어 장치, 소켓, 프로세스 정보 등도 파일 인터페이스로 다룬다는 관점이 중요합니다. 모든 자원이 일반적인 디스크 파일이라는 뜻은 아닙니다.

## 2. 리눅스 디렉터리 구조와 경로

### 주요 디렉터리

- `/`: 최상위 루트 디렉터리.
- `/bin`: 기본 실행 프로그램.
- `/boot`: 커널과 부트로더 관련 파일.
- `/dev`: 디바이스 장치 파일.
- `/etc`: 시스템 설정 파일.
- `/home`: 일반 사용자들의 홈 디렉터리.
- `/lib`: 공유 라이브러리.
- `/lost+found`: 지원하는 파일 시스템에서 복구된 파일을 담는 용도.
- `/media`, `/mnt`: 저장 장치 등의 파일 시스템을 마운트하는 위치.
- `/opt`: 추가 프로그램을 설치하는 위치.
- `/proc`: 커널과 현재 프로세스의 정보를 파일 형태로 보여주는 가상 파일 시스템.
- `/root`: 최고 관리자 root의 홈. `/`와 다른 경로이며 일반 사용자 홈과 분리됩니다.
- `/sbin`: 시스템 관리용 프로그램.
- `/srv`: 시스템이 제공하는 서비스의 데이터.
- `/tmp`: 임시 파일.
- `/usr`: 사용자 프로그램과 이를 지원하는 파일.
- `/var`: 로그 등 계속 변하는 데이터.

위 목록은 강의가 설명하는 기본 구조입니다. 배포판 구성에 따라 `/bin` 등이 `/usr/bin`으로 연결되는 등 세부 구현은 달라질 수 있습니다.

### 절대 경로와 상대 경로

- **절대 경로**: `/`에서 시작하여 전체 위치를 나타냅니다. 예: `/home/user/aaaa`.
- **상대 경로**: 현재 작업 디렉터리를 기준으로 나타냅니다. 예: `aaaa`, `./aaaa`, `../aaaa`.
- `.`: 현재 디렉터리.
- `..`: 상위 디렉터리.
- `~`: 셸에서 현재 사용자의 홈 디렉터리로 확장되는 표기. 홈이 `/home/user`라면 `~/aaaa`는 `/home/user/aaaa`를 뜻합니다.

> 강의에서는 `~/`를 상대 경로와 함께 설명합니다. 엄밀히는 현재 위치를 기준으로 계산하는 `./`와 달리, 셸의 홈 경로 확장이라는 점을 구분하면 혼동이 줄어듭니다.

## 3. 경로 확인·이동·목록

### pwd — 현재 위치

`pwd`는 print working directory입니다. 현재 작업 디렉터리의 경로를 출력합니다. 터미널을 시작하면 일반적으로 홈 디렉터리에 위치하며 프롬프트의 `~`로 표시되기도 합니다.

~~~bash
pwd
~~~

### cd — 디렉터리 이동

`cd`는 change directory입니다. 절대 경로와 상대 경로를 모두 사용할 수 있습니다.

~~~bash
cd ../       # 상위 디렉터리
pwd
cd ~         # 자신의 홈
cd /home     # 절대 경로로 이동
cd           # 인자를 생략해도 홈으로 이동
~~~

예를 들어 `/home/user`에서 `cd ../`를 하면 `/home`으로 이동합니다.

### ls — 파일·디렉터리 목록

형태는 `ls [옵션] [경로]`이며, 경로를 생략하면 현재 디렉터리입니다. 전체 옵션은 `ls --help`로 확인합니다.

- `-a`: 숨김 항목을 포함한 모든 항목.
- `-l`: 상세한 long listing 형식.
- `-Z`: SELinux 보안 정보.
- `-s`: 각 항목에 할당된 저장 공간 크기.
- `-S`: 파일 크기를 기준으로 정렬.
- `-h`: 크기를 K, M 등 사람이 읽기 쉬운 단위로 표현.
- `-i`: inode 번호.
- `-R`: 하위 디렉터리까지 재귀적으로 표시.

~~~bash
ls -al
ls -ali
~~~

상세 목록의 한 줄은 대체로 **종류/권한 → 링크 수 → 소유자 → 그룹 → 크기 → 수정 시간 → 이름** 순서입니다. 맨 앞의 `d`는 디렉터리, `-`는 일반 파일, `l`은 심볼릭 링크를 뜻합니다. 권한은 [사용자와 그룹](08_users_and_groups.md)에서 자세히 다룹니다.

커널에서 일반 파일과 디렉터리를 공통된 파일 관리 구조로 다루기 때문에 설명에 ‘파일’이라는 표현이 함께 쓰이기도 합니다. 목록의 종류 표시는 사용자가 이를 구분할 수 있도록 제공됩니다.

## 4. 디렉터리 생성·삭제

`mkdir`는 make directory, `rmdir`는 remove directory입니다.

~~~bash
cd ~/Desktop
mkdir file_and_directory
ls
cd file_and_directory
mkdir dir1
ls
rmdir dir1
ls
~~~

`rmdir`는 **비어 있는 디렉터리**를 지웁니다. 내용이 있는 디렉터리를 지우려면 먼저 내용을 정리하거나 재귀 삭제 기능이 필요하지만, 삭제 범위를 반드시 확인해야 합니다.

## 5. 파일 생성·읽기·쓰기

### touch — 빈 파일 생성

~~~bash
touch file1
touch file2 file3
ls -al
~~~

존재하지 않는 파일에는 크기 0의 파일을 만듭니다. 이미 존재하는 파일에 사용하면 내용을 비우는 것이 아니라 시간 정보를 갱신합니다. 강의는 파일 생성 용도를 중심으로 설명합니다.

### cat — 내용 출력과 입력 연결

`cat`은 concatenate에서 나온 이름입니다. `cat file1`은 파일 내용을 표준 출력에 보냅니다. 셸의 출력 리다이렉션을 결합하면 터미널 입력을 파일에 쓸 수 있습니다.

~~~bash
cat > file1 << EOF
Hello Linux!
EOF
cat file1
ls -al
~~~

- `>`: 지정한 파일로 출력을 보내며 기존 내용은 덮어씁니다.
- `<< EOF`: `EOF`만 적힌 줄을 만날 때까지 입력을 제공하는 here-document입니다. 종료 표식 자체는 파일 내용에 포함하지 않습니다.
- 예제 결과는 `Hello Linux!` 뒤에 줄바꿈이 붙은 13바이트입니다.
- `touch` 자체는 내용을 입력하거나 읽는 명령이 아닙니다. 편집기나 다른 명령을 조합해야 합니다.

### head / tail — 앞·뒤 부분만 출력

- `head`: 앞부분을 출력.
- `tail`: 뒷부분을 출력.
- `-c 바이트수`: 지정한 바이트 수.
- `-n 줄수`: 지정한 줄 수.

~~~bash
head -c 5 file1
tail -c 5 file1
head -n 1 file1
tail -n 1 file1
~~~

위 `head`의 5바이트는 `Hello`입니다. `tail`의 5바이트는 `nux!`와 줄바꿈이므로 화면에는 네 글자만 보일 수 있습니다. **바이트 수와 보이는 글자 수는 다를 수 있으며**, 특히 한글 같은 멀티바이트 문자에서 주의합니다.

## 6. 이동·복사·삭제

### mv — 이동·이름 변경

형태: `mv [옵션] 원래경로 대상경로`. 파일뿐 아니라 디렉터리에도 사용합니다. 대상이 디렉터리라면 기존 이름을 유지한 채 그 안으로 이동합니다.

- `-b`: 기존 대상 파일을 백업.
- `-f`: 덮어쓸지 묻지 않음.
- `-i`: 덮어쓰기 전 확인.
- `-n`: 이미 존재하는 대상은 덮어쓰지 않음.

~~~bash
mkdir dir1
mv file1 dir1/file1
mv dir1/file1 .
~~~

### cp — 복사

형태: `cp [옵션] 원래경로 대상경로`.

- `-r`: 디렉터리의 내용을 재귀적으로 복사.
- `-f`: 필요하면 기존 대상 파일을 제거하고 다시 생성하여 복사하는 강제 동작.
- `-i`: 덮어쓰기 전 확인.
- `-p`: 가능하면 모드·소유권·시간 정보를 보존.

~~~bash
cp file1 dir1/file1
cat dir1/file1
~~~

이동과 달리 원래 파일이 남고, 복사본에서도 같은 내용이 출력됩니다. 같은 이름의 대상이 있으면 덮어쓸 수 있으므로 실습에서는 대상 상태를 확인합니다.

### rm — 삭제

형태: `rm [옵션] 경로`.

- `-f`: 없는 파일에 대한 오류와 확인 질문 등을 억제하는 강제 옵션. 권한을 무시하는 기능은 아닙니다.
- `-r`: 하위 내용까지 재귀적으로 삭제.
- `-d`: 비어 있는 디렉터리 삭제.
- `-v`: 처리한 대상을 출력.

일반적인 `rm dir1`은 디렉터리를 지우지 못합니다. 강의에서는 `rm -rf dir1`로 디렉터리와 그 내용을 지우는 모습을 보여줍니다.

> **삭제 주의:** `rm`은 보통 휴지통으로 보내지 않습니다. `-rf`는 잘못 지정한 경로 아래의 데이터를 묻지 않고 지울 수 있습니다. 실습용 `dir1`인지 `pwd`와 `ls`로 확인한 뒤 사용하고, 홈·루트·Desktop 전체 또는 실제 자료가 있는 폴더에는 적용하지 마세요. 단순 파일 삭제 예시는 `rm file1`입니다.

## 7. inode와 링크

### 파일 시스템과 inode

**파일 시스템(File System)**은 파일을 생성하고 읽고 쓰기 위해 저장 공간과 정보를 관리하는 방식입니다. 강의는 ext 계열, NTFS, OverlayFS를 예로 들며 Ubuntu에서 흔히 사용하는 ext4를 소개합니다.

**inode**는 파일의 메타데이터를 관리합니다. 강의에서 다루는 정보는 다음과 같습니다.

- inode 번호.
- 파일 모드.
- 링크 개수.
- 소유자 UID와 그룹 GID.
- 파일 크기와 데이터 저장 위치.
- 최종 접근·내용 수정·inode 정보 변경 시각.

inode 번호는 파일 시스템 안에서 식별에 사용됩니다. 따라서 서로 다른 파일 시스템의 번호만 비교해 같은 파일이라고 판단하지 않습니다.

### 하드 링크

**하드 링크(Hard Link)**는 서로 다른 디렉터리 항목이 같은 inode를 가리키게 합니다.

- 경로는 다르지만 같은 파일 데이터입니다.
- 링크를 하나 만들면 inode의 링크 수가 하나 늘어납니다.
- 원래 이름을 지워도 다른 하드 링크가 남아 있으면 내용에 계속 접근할 수 있습니다.
- 강의 도식의 변화: 파일 A만 있을 때 링크 수 1 → B를 만들면 2 → A를 지우면 1.

> 강의는 링크 수를 참조 횟수로 단순화합니다. 실제 파일 삭제 시 데이터 회수에는 열린 파일의 참조도 관계합니다. “링크 수가 0이면 즉시 모든 데이터가 사라진다”로 단정하지 않습니다.

### 심볼릭 링크

**심볼릭 링크(Symbolic/Soft Link)**는 별도의 inode를 가지며, 다른 파일의 경로를 저장합니다. Windows 바로 가기와 비슷한 방향의 개념입니다.

- 원본과 링크는 서로 다른 inode를 가집니다.
- 원본을 제거하거나 옮겨 저장된 경로가 유효하지 않으면 링크가 깨집니다.
- 원본의 inode 링크 수를 하드 링크처럼 증가시키지 않습니다.

### ln — 링크 생성

형태: `ln [옵션] 원본경로 링크이름`. 기본 동작은 하드 링크이며 `-s`가 심볼릭 링크입니다.

- `-b`: 같은 이름의 대상이 있으면 백업.
- `-d`: 관리자에게 디렉터리 하드 링크를 시도하도록 허용하지만, 파일 시스템이 지원해야 하며 일반적인 디렉터리 링크 실습 방법이 아닙니다.
- `-f`: 기존 대상 제거.
- `-s`: 심볼릭 링크.
- `-n`: 대상 링크 이름이 디렉터리를 가리키는 심볼릭 링크일 때 그 링크 자체를 일반 파일처럼 취급.

~~~bash
touch file1
ln file1 hardlink_file
ln -s file1 symlink_file1
ls -ali
~~~

확인할 결과:

- `file1`과 `hardlink_file`의 inode 번호가 같고 링크 수가 증가합니다.
- `symlink_file1`은 inode 번호가 다르며 `-> file1`처럼 대상이 표시됩니다.
- 강의 화면의 inode 번호 `2238316`은 해당 실습 환경의 예시일 뿐, 다른 환경에서도 같은 수치가 나오는 것은 아닙니다.

> **강의 옵션표 보충:** `ln -n`은 원본 심볼릭 링크를 따라가는 옵션이 아닙니다. 원본을 따라가 하드 링크를 만드는 옵션은 `-L`입니다. `-d`도 지원 여부와 관리자 제약이 있습니다. [GNU ln 매뉴얼](https://man7.org/linux/man-pages/man1/ln.1.html)

## 8. find로 탐색

형태: `find [옵션] 탐색시작경로 [표현식...]`. 시작 위치에서 하위 디렉터리를 순회하여 조건에 맞는 파일을 찾습니다.

### 탐색 옵션

- `-P`: 심볼릭 링크를 따라가지 않고 링크 자체를 검사. 기본값.
- `-L`: 심볼릭 링크의 대상을 따라 검사.
- `-H`: 탐색 중 만나는 링크는 따라가지 않지만, 명령줄에 시작점으로 직접 준 심볼릭 링크는 따라감.
- `-D 추가옵션`: 진단·디버깅 정보.
- `-O레벨`: 탐색 표현식의 최적화 수준.

### 강의에서 다루는 표현식

- `-name 이름`: 파일 이름.
- `-user 사용자`, `-group 그룹`: 소유자·그룹 이름.
- `-uid 번호`, `-gid 번호`: UID·GID.
- `-perm 권한`: 지정한 권한 조건.
- `-type 종류`: 파일 종류. 예: `-type d`는 디렉터리.
- `-maxdepth 깊이`: 최대 탐색 깊이.
- `-mindepth 깊이`: 조건을 적용할 최소 깊이.

~~~bash
mkdir dir1
touch file1 dir1/file1
find . -name 'file1'
find . -mindepth 2 -name 'file1'
find . -maxdepth 1 -name 'file1'
find . -name '*file1'
~~~

- 첫 번째 검색은 `./file1`, `./dir1/file1`처럼 모든 해당 이름을 찾습니다.
- `-mindepth 2`는 예제에서 `./dir1/file1`을 찾습니다.
- `-maxdepth 1`은 예제에서 `./file1`을 찾습니다.
- `*`는 길이 0 이상의 문자열과 맞는 와일드카드입니다. 따라서 `*file1`은 `file1`, `symlink_file1`처럼 끝나는 이름을 찾습니다.
- 패턴에 따옴표를 붙여 셸이 먼저 확장하지 않고 `find`에 그대로 전달합니다.

> **깊이 보충:** 강의는 현재 위치를 depth 1이라고 설명하지만 GNU find는 **시작점 `.`을 depth 0**으로 셉니다. 그 안의 `file1`은 1, `dir1/file1`은 2입니다. 또한 `-H`는 시작점 링크에 예외가 있습니다. [GNU find 매뉴얼](https://man7.org/linux/man-pages/man1/find.1.html)
