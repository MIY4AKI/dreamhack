## 1. I/O와 파일 디스크립터

**I/O(Input/Output)**는 입력과 출력입니다. 키보드·마우스·모니터뿐 아니라 네트워크 통신도 입출력입니다. I/O를 적절하게 다루지 못하면 CPU와 장치 사이의 병목이나 잘못된 입력 처리로 프로그램이 원하는 동작을 하지 못할 수 있습니다.

프로세스는 파일이나 입출력 장치의 커널 내부 객체를 직접 조작하는 대신, 운영체제가 제공한 **파일 디스크립터(File Descriptor, fd)**를 사용합니다. fd는 열린 파일 등을 가리키는 작은 0 이상의 정수입니다.

강의의 구조 그림에서 연결되는 세 요소를 구별합니다.

1. **프로세스의 File Descriptor Table**: 프로세스가 fd 번호를 인덱스로 사용하는 표.
2. **Open File Description**: 열린 파일의 현재 오프셋과 상태 등을 관리하는 커널의 열린 파일 정보.
3. **inode 등 실제 파일 정보**: 파일 메타데이터와 저장된 데이터로 연결되는 정보.

즉, fd 번호 자체가 디스크의 물리 주소나 inode 번호인 것은 아닙니다. 같은 번호라도 프로세스마다 다른 파일을 가리킬 수 있습니다. 파일뿐 아니라 파이프나 소켓도 fd로 다룹니다.

## 2. 표준 입력·출력·에러

일반적인 셸 프로그램은 다음 세 fd를 열어 둔 채 시작합니다.

- **0 — stdin**: 표준 입력.
- **1 — stdout**: 표준 출력.
- **2 — stderr**: 표준 에러 출력.

기본 터미널에서는 이들이 터미널 입출력에 연결되어 있지만 파일이나 파이프로 바꿀 수도 있습니다. 그래서 프로그램이 별도로 `open()`을 호출하지 않았어도 입력을 받고 출력을 보낼 수 있습니다.

새 파일을 열면 보통 3 이상의 번호를 받습니다. 다만 이는 0·1·2가 이미 열린 일반적인 상황의 예시입니다. `open()`은 실제로 **현재 사용하지 않는 가장 작은 fd 번호**를 반환하므로 0·1·2 중 닫힌 번호가 있으면 그 번호를 사용할 수 있습니다. [Linux open 매뉴얼](https://man7.org/linux/man-pages/man2/open.2.html)

`/proc/PID/fd/`에는 그 프로세스가 가진 fd를 확인할 수 있는 항목들이 있습니다. 실제 fd 표가 이 폴더에 저장되어 있다는 뜻이 아니라, 커널이 해당 정보를 파일 인터페이스로 보여줍니다.

## 3. 파이프

**파이프(Pipe)**는 앞 명령의 표준 출력을 뒤 명령의 표준 입력으로 연결합니다. `|`는 독립된 실행 명령이 아니라 셸 문법입니다.

~~~bash
명령A | 명령B
~~~

기본적으로 stdout만 이어지며 stderr는 자동으로 같은 파이프에 들어가지 않습니다.

### 안전한 실습 준비

원문은 먼저 `cd ~/Desktop`, `ls -al`, `rm -rf ./*`로 바탕화면의 기존 실습 자료를 지우는 과정을 보여줍니다. **이 삭제 명령을 실제 Desktop에서 따라 하면 개인 자료를 잃을 수 있으므로 실행하지 마세요.** 여기서는 비어 있는 별도 실습 폴더를 만드는 방식으로 바꿉니다.

~~~bash
mkdir fd_practice
cd fd_practice
pwd
ls -al
~~~

이미 같은 폴더가 존재하면 새 이름을 선택하고 기존 내용을 먼저 확인합니다. 요약 작성 중 원문의 삭제를 실행하지 않았습니다.

### 프로그램 출력 연결 예시

강의의 `pipe.c`는 한 줄을 받아 `output is "입력내용"`으로 출력합니다. 원문에는 `scanf("%[^\n]s", buffer)`라는 폭 제한 없는 입력이 있어 긴 입력에 안전하지 않습니다. 아래는 같은 학습 목적을 유지하되 256바이트 버퍼에 맞게 읽기 폭과 입력 성공 확인을 보충한 예입니다.

~~~c
#include <stdio.h>

int main(void) {
    char buffer[0x100];
    if (scanf("%255[^\n]", buffer) == 1) {
        printf("output is \"%s\"\n", buffer);
    }
}
~~~

~~~bash
gcc -o pipe pipe.c
./pipe
./pipe | ./pipe
~~~

첫 실행에 `hello pipe!`를 입력하면 다음이 나옵니다.

~~~text
output is "hello pipe!"
~~~

두 프로그램을 파이프로 연결하면 첫 출력이 두 번째 입력이므로 다음처럼 한 겹 더 감싼 문자열이 나옵니다.

~~~text
output is "output is "hello pipe!""
~~~

이 예시에서 `pipe`는 실습 실행 파일 이름이고, `|`가 실제로 입출력을 연결하는 문법입니다.

## 4. 리다이렉션

**리다이렉션(Redirection)**은 표준 입력·출력 등의 연결 대상을 재지정하는 셸 문법입니다.

- `명령 < 파일`: 파일 내용을 stdin에 연결.
- `명령 > 파일`: stdout을 파일로 연결. 기존 파일은 비우고 덮어씀.
- `명령 >> 파일`: stdout을 기존 파일 뒤에 덧붙임.
- `명령 << 종료표식`: 종료표식을 만날 때까지 작성한 내용을 stdin으로 제공하는 here-document.

`<<`는 “기존 입력에 덧붙이는 연산”이 아니라 여러 줄 입력을 지정하는 별도 문법입니다.

### 강의의 파일 예제

~~~bash
echo "hello redirection" > redirection.txt
echo "hello redirection2" >> redirection.txt
cat < redirection.txt
~~~

최종 파일 내용:

~~~text
hello redirection
hello redirection2
~~~

첫 명령이 새 파일 내용을 만들고, 두 번째는 기존 내용을 유지한 채 추가합니다. 세 번째는 그 파일을 cat의 입력으로 전달하여 출력합니다.

### 에러 출력과 fd 복제

~~~bash
명령 2> error.txt
명령 2>&1
명령 > output.txt 2>&1
~~~

- `2>`: stderr를 파일로 연결.
- `2>&1`: fd 2가 **그 시점의 fd 1과 같은 대상**을 사용하도록 복제.
- `> output.txt 2>&1`: stdout을 파일로 바꾼 뒤 stderr도 같은 파일로 연결.
- `명령 2>&1 > output.txt`는 순서가 반대이므로 stderr가 기존 stdout 대상에 남을 수 있습니다. 셸은 리다이렉션을 왼쪽부터 처리합니다.

### 출력을 파일로 쓰면서 여러 줄 입력하기

~~~bash
cat > memo.txt << EOF
first line
second line
EOF
~~~

원문의 `A > B << C` 형태에 대응합니다. B는 출력 파일, C는 입력 종료 표식입니다. 종료 표식은 한 줄에 단독으로 적으며 파일에 포함되지 않습니다. 꺾쇠는 입력과 출력의 연결이고, 종료 표식은 here-document의 입력 범위를 정한다는 점을 구별합니다.

## 5. grep

`grep`은 정규식에 맞는 내용을 검색하는 명령입니다. 강의는 vi/ed 계열의 global·regular expression·print 명령에서 유래한 이름을 소개합니다.

형태:

~~~text
grep [옵션] 패턴 [파일...]
~~~

파일을 주지 않으면 stdin을 읽을 수 있으므로 파이프와 함께 자주 사용합니다. 디렉터리 내부는 `-r` 같은 재귀 옵션으로 검색합니다.

### 옵션

- `-c`: 일치하는 **줄 수**만 출력. 같은 줄에 여러 번 등장해도 줄 하나입니다.
- `-o`: 일치한 부분만 출력. 기본값은 일치하는 줄 전체.
- `-i`: 대소문자 구분 없이 검색.
- `-h`: 출력에 파일 이름을 붙이지 않음.
- `-l`: 일치 내용이 있는 파일의 이름만 출력.
- `-v`: 일치하지 않는 줄을 출력.
- `-r`: 하위 디렉터리 파일을 재귀적으로 검색.
- `-n`: 일치한 줄의 번호도 출력.
- `-w`: 독립된 단어의 형태로 일치하는 경우 검색.

### 파이프와 직접 파일 입력

~~~bash
cat redirection.txt | grep 'redirect'
grep 'redirect' redirection.txt
grep 'on$' redirection.txt
grep -r 'redirect' .
~~~

- 앞의 두 명령은 `redirect`를 포함하는 두 줄을 모두 찾습니다.
- `'on$'`의 `$`는 줄의 끝을 뜻합니다. `hello redirection`은 맞고 `hello redirection2`는 맞지 않습니다.
- `-r`은 현재 디렉터리 아래 파일 내용까지 검색합니다.
- `'redirect'`처럼 실제 셸에서 사용할 때는 일반적인 ASCII 따옴표를 씁니다. 문서용 곡선 따옴표를 그대로 복사하지 않습니다.

`find`는 **파일의 이름·위치·속성**을 찾고, `grep`은 주로 **파일이나 입력의 내용**을 찾는다는 차이도 기억합니다.

- [ ] `>`, `>>`, `<`, `<<`를 구분한다.
- [ ] `2>`와 `2>&1`의 차이 및 리다이렉션 순서의 영향을 안다.

- [ ] grep의 줄 전체 출력·부분 출력·반전·재귀·줄 번호 옵션을 사용할 수 있다.
