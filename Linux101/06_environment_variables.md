## 1. 환경 변수와 명령 검색

**환경 변수(Environment Variable)**는 실행 중인 프로세스의 동작에 영향을 주는 설정 값입니다. 보통 **키=값** 형태로 전달합니다.

프로그램이 참고하는 경로, 사용자 이름, 언어 설정, 응용 프로그램 설정, API 키 등을 담을 수 있습니다. 어떤 키를 어떤 의미로 해석하는지는 셸이나 프로그램의 규칙에 따라 달라집니다.

터미널에서 `/bin/sh` 대신 `sh`만 입력해도 실행 파일을 찾는 데에는 `PATH`가 관여합니다. 셸은 외부 명령을 검색할 때 PATH에 나열된 디렉터리를 순서대로 확인합니다. 앞에 있는 디렉터리에서 해당 이름을 찾으면 그 프로그램을 선택합니다.

- PATH에 `/bin`이 포함되어 있으면 그곳의 `sh`를 찾을 수 있습니다.
- PATH 순서를 바꾸면 같은 이름의 다른 실행 파일이 선택될 수 있습니다.
- `/bin/sh`, `./hello`처럼 슬래시가 있는 경로를 지정하면 그 경로를 사용합니다.
- 셸 내장 명령이나 alias 등의 처리도 있으므로, 모든 이름이 무조건 PATH 검색부터 거치는 것은 아닙니다.

환경 변수는 프로세스별로 존재합니다. 현재 셸에서 바꾼 환경은 그 셸이 나중에 실행하는 자식 프로그램에 전달할 수 있지만, 이미 실행 중인 다른 프로그램이나 부모 셸까지 자동으로 변경하는 것은 아닙니다.

## 2. 대표 변수

- `PATH`: 외부 실행 파일을 찾을 디렉터리 목록. Unix에서는 보통 `:`로 구분합니다.
- `HOME`: 사용자의 홈 디렉터리.
- `LANG`: 기본 언어·로케일 관련 설정.
- `PWD`: 현재 작업 디렉터리 경로를 셸이 관리하는 값.
- `USER`: 사용자 이름.
- `SHELL`: 사용자의 로그인 셸 경로. 지금 중첩해서 실행 중인 셸과 항상 일치하지는 않습니다.
- `MAIL`: 메일 보관 경로.
- `UID`: 사용자 ID. Bash에서는 읽기 전용 셸 변수이며, 기본적으로 반드시 export된 환경 변수라는 뜻은 아닙니다.
- `LS_COLORS`: `ls`의 파일 유형별 색상 표시 설정 값. 색상 옵션 파일의 경로 자체를 뜻하는 것은 아닙니다.

> 구분: 모든 셸 변수가 환경 변수인 것은 아닙니다. 환경 변수로 내보낸 값은 `env` 출력과 자식 프로세스 환경에 나타납니다. `UID`처럼 셸이 제공하는 변수는 셸 안에서 `$UID`로 읽을 수 있어도 환경에 export되어 있지 않을 수 있습니다. [Bash 변수와 환경 매뉴얼](https://man7.org/linux/man-pages/man1/bash.1.html)

## 3. env로 확인·일시 변경

형태:

~~~text
env [옵션] [NAME=VALUE ...] [명령어]
~~~

- 인자가 없는 `env`: 현재 프로세스 환경 출력.
- `-i`: 기존 환경을 무시하고, 지정한 변수만으로 명령 실행.
- `-u 변수이름`: 해당 변수를 제외한 환경으로 명령 실행.

~~~bash
env
env -i PATH=/bin sh
env -u HELLO sh
~~~

강의는 PATH 값이 달라지면 같은 `sh` 명령도 찾지 못할 수 있다는 예시를 보여줍니다. `env -i`를 사용할 때 필요한 PATH 등을 명시하면 프로그램을 찾는 동작을 관찰할 수 있습니다.

`env`는 해당 명령의 환경을 구성하는 것이므로 호출한 부모 셸의 설정을 영구적으로 바꾸는 명령이 아닙니다. 환경에 PATH가 없는 경우와 빈 PATH를 준 경우도 구분해야 하며, 실행 도구의 기본 검색 규칙에 따라 동작이 달라질 수 있습니다.

> 개인정보 주의: `env` 출력에는 토큰이나 API 키 등 비밀 값이 포함될 수 있습니다. 출력 전체를 공개 채팅·게시물에 그대로 붙여 넣지 마세요.

## 4. export로 설정

`export`는 셸 변수를 자식 프로그램의 환경으로 내보내는 셸 내장 명령입니다.

~~~bash
export HELLO="hello environ!"
echo "$HELLO"
env
export -p
~~~

순서대로 보면 다음과 같습니다.

1. `HELLO` 값을 설정하면서 export 표시를 합니다.
2. `$HELLO`로 값에 접근합니다.
3. `echo`가 `hello environ!`을 출력합니다.
4. `env`에서 `HELLO=hello environ!`을 확인할 수 있습니다.
5. `export -p`는 export된 셸 변수를 셸 선언 형식으로 출력합니다.

강의는 `export -p`를 `env`와 같은 확인 용도로 설명합니다. 목적은 비슷하지만 출력 형식과 다루는 대상이 완전히 동일한 명령은 아닙니다.

### 셸 변수와 환경 변수의 차이

앞 예제의 export 표시가 남아 있지 않도록 먼저 변수를 해제한 뒤 비교합니다.

~~~bash
unset HELLO
HELLO="hello environ!"
export HELLO
~~~

값을 대입하는 두 번째 줄은 현재 셸 변수만 설정하고, 세 번째 줄이 자식에게 전달할 환경 변수로 표시합니다. `export HELLO="hello environ!"`은 두 작업을 함께 수행합니다. 이미 export된 변수는 값만 다시 대입해도 export 표시가 유지됩니다. `unset HELLO`는 변수와 그 표시를 함께 제거합니다.

값을 읽는 실제 문법은 `$HELLO` 또는 `${HELLO}`입니다. 강의의 `$[환경 변수 KEY]` 표기는 설명용 자리표시자로 읽고 그대로 실행하지 않습니다. 공백 등이 있는 값을 안전하게 다루려면 `"$HELLO"`처럼 따옴표를 사용합니다.

## 5. unset으로 해제

형태: `unset 변수이름`.

~~~bash
unset HELLO
env
echo "$HELLO"
~~~

현재 셸의 `HELLO` 설정이 사라지고, 이후 실행하는 자식의 환경에도 전달되지 않습니다. `env`에서 더 이상 해당 변수를 찾을 수 없고 `echo`는 기본적인 상황에서 빈 값을 출력합니다.

`env -u HELLO 명령`이 **특정 명령의 환경에서만** 제외하는 것과, `unset HELLO`가 **현재 셸의 변수 자체를** 없애는 것은 다릅니다.

## 6. 복습 체크

- [ ] HOME, LANG, PWD, USER, SHELL의 역할을 구분한다.
- [ ] 셸 변수와 export된 환경 변수의 차이를 설명한다.
- [ ] `env`, `env -i`, `env -u`의 범위를 구분한다.
- [ ] `export`, `$변수이름`, `unset`을 사용할 수 있다.
- [ ] 환경 출력에 비밀 값이 포함될 수 있음을 알고 공유 전 확인한다.
