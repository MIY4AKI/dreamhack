## 1. 터미널과 셸

GUI(Graphical User Interface)는 창·아이콘을 조작하는 방식이고, CUI(Character User Interface)는 문자 명령을 입력하는 방식이다. 보안 공부에서는 터미널을 통한 리눅스 조작이 빈번하므로, 명령어를 직접 실행하면서 익히는 것이 중요하다.

셸은 사용자와 운영체제 사이의 명령 인터페이스다. 입력을 해석하고 프로그램 실행을 요청한 뒤 그 결과를 사용자에게 보여 준다. 우분투 데스크톱의 터미널을 열면 보통 Bash 셸이 함께 실행된다.

- Windows/Linux 기준 VM 터미널 단축키: `Ctrl + Alt + T`.
- 강의의 Mac 기준 단축키: `Control + Option + T`.
- 프롬프트 예: `user@user-VirtualBox:~$`.
  - `user`: 현재 사용자, `user-VirtualBox`: 호스트명, `~`: 홈 디렉터리.
  - 프롬프트가 나타나면 다음 명령을 받을 준비가 된 것이다.
  - 노트의 코드에는 프롬프트를 생략했다. `$`나 출력 결과까지 입력하지 않는다.

```bash
id
```

출력의 `uid=1000(user)`는 사용자 ID, `gid=1000(user)`는 기본 그룹 ID, `groups=...`는 소속 그룹 목록이다. 숫자와 그룹 목록은 계정·설치 환경마다 달라질 수 있다.

## 2. 기본 명령어 17개

### 1) `sudo apt update` — 설치 가능한 패키지 목록 갱신

저장소에서 패키지 목록과 설치 가능한 버전 정보를 가져온다. **설치된 패키지 자체를 업그레이드하는 명령은 아니다.** `sudo`는 허가된 사용자에게 관리자 권한으로 명령을 실행하게 한다.

```bash
sudo apt update
```

강의 출력은 저장소 조회, 목록 읽기, 의존성 계산, 업그레이드 가능 패키지 수를 보여 준다. 비밀번호 입력 중 문자가 보이지 않는 것은 정상이다.

### 2) `sudo apt upgrade` — 설치된 패키지 업그레이드

```bash
sudo apt upgrade
```

목록에 따라 설치된 패키지를 새 버전으로 올린다. 취약한 구버전을 계속 쓰지 않도록 주기적으로 갱신하는 것이 중요하다. 강의의 `0 upgraded ... 3 not upgraded`는 해당 시점의 예시일 뿐 항상 같은 결과가 나오는 것은 아니다.

출력에서 함께 접하는 명령:

- `apt list --upgradable`: 업그레이드 가능한 패키지 확인.
- `sudo apt autoremove`: 더 이상 필요하지 않은 자동 설치 의존성 제거. 제거 목록을 먼저 확인한다.
- `pro config set apt_news=false`: 강의 로그에 등장하는 APT 안내 메시지 설정이며, 패키지 업그레이드의 필수 단계는 아니다.

### 3) `id` — 사용자·그룹 ID 확인

현재 계정의 UID, GID, 소속 그룹을 확인한다. 자원에 접근할 권한이 있는지 판단할 때 출발점이 된다.

### 4) `pwd` — 현재 작업 경로 확인

Print Working Directory의 약자다.

```bash
pwd
# 예: /home/user
```

### 5) `ls` — 디렉터리 내용 조회

```bash
ls
ls -l
ls -l /
```

- 인자 없이 실행하면 현재 디렉터리의 이름 목록을 출력한다.
- `-l`은 권한·소유자·소유 그룹·크기·수정 시각 등을 함께 보여 준다.
- 경로 인자를 주면 이동하지 않고 해당 디렉터리를 볼 수 있다.
- 강의의 홈 목록은 Desktop, Documents, Downloads, Music, Pictures, Public, snap, Templates, Videos 등이다. 설치 방식과 언어에 따라 다를 수 있다.

### 6) `cd` — 작업 디렉터리 변경

Change Directory의 약자다. 절대 경로는 `/`에서 출발하고, 상대 경로는 현재 위치를 기준으로 해석한다.

```bash
cd /
pwd
cd /home/user
cd ..
pwd
cd ~
cd -
```

- `/home/user`: 절대 경로.
- `..`: 부모 디렉터리. `/home/user`에서 이동하면 `/home`.
- `~`: 현재 사용자의 홈 디렉터리.
- `cd -`: 이전 작업 디렉터리로 돌아가기. 일반 파일 경로의 `-`가 언제나 이전 디렉터리를 뜻하는 것은 아니다.

### 7) `mkdir` — 디렉터리 생성

```bash
mkdir new_dir
ls -l
cd new_dir
```

현재 위치 아래에 `new_dir`를 만든다. 이후 파일 관련 예제는 이 실습 디렉터리 안에서 진행한다.

### 8) `touch` — 빈 파일 생성

```bash
touch new_file
ls -l
```

없는 이름을 지정하면 크기 0의 파일이 생긴다. 이미 존재하는 파일에 실행하면 내용을 비우는 것이 아니라 시각 정보를 갱신한다는 점도 구별한다.

### 9) `mv` — 이동 또는 이름 변경

```bash
mv new_file old_file
mv old_file ..
```

첫 명령은 같은 디렉터리에서 이름을 바꾸고, 둘째는 부모 디렉터리로 이동한다. 대상 이름에 기존 파일이 있으면 덮어쓸 수 있으므로 경로를 확인한다.

### 10) `rm` — 삭제

```bash
touch abcd
rm abcd
mkdir dir
rm -r dir
```

파일은 `rm`, 디렉터리와 그 안의 내용은 재귀 옵션 `-r`로 삭제한다. **휴지통 이동이 아니므로 실습용으로 직접 만든 대상에만 실행한다.**

### 11) `cat` — 파일 내용 출력

```bash
cat /etc/passwd
```

강의에서는 사용자 정보 파일을 읽는 데 사용한다. 파일명이 아니라 경로를 인자로 넘긴다. `/etc/passwd`는 이름과 달리 현대 리눅스에서 일반적으로 실제 비밀번호 해시를 저장하는 파일은 아니다.

### 12) `file` — 파일 유형 판별

```bash
file /bin/ls
```

강의 결과는 ELF 64-bit, x86-64, 동적 링크, PIE 실행 파일 등의 속성을 보여 준다. `/bin/ls`는 `ls`를 입력했을 때 실행되는 프로그램이다. 아키텍처·빌드 정보는 시스템별로 달라진다.

### 13) `echo` — 문자열 출력과 파일 저장

```bash
echo "Hello world!"
echo "Hello world!" > hello
cat hello
```

첫 명령은 화면 출력, 둘째는 `hello` 파일에 출력 저장이다. `>`는 기존 파일을 덮어쓸 수 있다.

### 14) `cp` — 복사

```bash
cp hello world
cp -r source_dir copied_dir
```

원본을 남기고 새 경로로 복사한다. 디렉터리를 내부 내용과 함께 복사하려면 강의에서 소개하는 재귀 옵션 `-r`을 붙인다.

### 15) `grep` — 일치하는 행 찾기

```bash
grep root /etc/passwd
```

`root`가 포함된 행을 출력한다. 사용자 이름이 root인 행만 찾는 것은 아니므로, 강의 예시에서는 `.../chroot/...`가 포함된 다른 계정의 행도 나온다.

### 16) `man` — 명령 매뉴얼 읽기

```bash
man cp
```

NAME, SYNOPSIS, DESCRIPTION, 옵션 설명 등의 항목을 확인한다. 강의 화면에는 `cp`의 `-a/--archive`, `--attributes-only`, `--backup` 등도 예시로 나타난다. `h`는 도움말, `q`는 매뉴얼 종료다. 모든 옵션을 처음부터 암기하기보다 필요할 때 매뉴얼을 확인한다.

### 17) `curl` — URL을 통한 데이터 전송

HTTP, HTTPS, FTP 등 다양한 프로토콜을 지원하며, 기본 형식은 `curl [옵션] URL`이다.

```bash
curl https://www.google.com
```

브라우저처럼 페이지를 그려 주는 것이 아니라 받은 HTML 등의 데이터를 출력한다. 강의의 주요 옵션:

- `-o file`: 받은 데이터를 지정한 파일에 저장.
- `-i`: 응답 헤더를 본문과 함께 출력.
- `-X "method"`: HTTP 요청 메서드 문자열 지정.
- `-d "key=value"`: 데이터를 전송하며, 일반적인 사용에서는 POST 요청이 된다.

강의는 워게임에서 직접 보이지 않는 명령 실행 결과를 풀이자가 관리하는 수신 서버에 POST하여 확인하는 활용도 소개한다. 핵심은 **명령 치환 결과를 `-d` 인자로 넘긴다**는 것이다. 아래는 같은 구조를 실습용 파일과 자리표시자로 바꾼 예다.

```bash
# 자신에게 허가된 실습 환경과 자신이 관리하는 수신 주소에만 사용
curl 'https://YOUR-LAB-ENDPOINT' -d "$(cat lab_output.txt)"
```

사용자 PC의 파일이나 타인의 데이터를 실제 외부 서버로 전송하는 예제가 아니다. 이 노트 작성 과정에서도 전송 명령을 실행하지 않았다.

## 3. 와일드카드

셸은 파일명 패턴을 실제 일치하는 경로로 확장할 수 있다.

- `?`: 문자 하나와 일치. `cat he?lo`는 `hello` 같은 이름을 찾는다.
- `*`: 빈 문자열을 포함해 임의 길이 문자열과 일치. `cat h*`는 h로 시작하는 이름을 찾는다.
- `[문자들]`: 괄호 안 문자 중 하나와 일치. `[abc]`는 a, b, c 중 하나다.
- `[시작-끝]`: 범위의 문자 하나와 일치. `test[0-9]`는 `test` 뒤에 숫자 하나가 붙은 이름이다.

```bash
touch test1 test2 test3
ls test[0-9]
# 예: test1 test2 test3
```

> 보충·정정: 원문의 `?`, `*` 설명은 a–z와 0–9를 중심으로 표현되어 있지만 실제로 그 문자들에만 제한되는 것은 아니다. `[a,b]`는 쉼표까지 후보에 포함하므로 문자 목록은 보통 `[ab]`처럼 쓴다. 기본 Bash에서 이름 맨 앞의 `.`은 명시적으로 맞춰야 하는 등 파일명 확장 규칙도 있다. [Bash 패턴 매칭](https://www.gnu.org/s/bash/manual/html_node/Pattern-Matching.html), [파일명 확장](https://www.gnu.org/s/bash/manual/html_node/Filename-Expansion.html).

## 4. 리다이렉션과 파이프

리다이렉션은 프로그램의 입력·출력 연결 대상을 바꾸는 것이다. 보통 키보드로 넣고 화면으로 보는 흐름을 파일이나 다른 프로그램으로 연결할 수 있다.

### `>` — 출력 저장, 기존 내용 덮어쓰기

```bash
ls test[0-9] > world
cat world
```

`world`가 없으면 생성되고 있으면 기존 내용이 교체된다. 화면 출력과 파일로 보낸 출력은 열 배치가 다를 수 있다. 강의에서는 파일에 test1, test2, test3이 한 줄씩 저장된다.

### `>>` — 출력 추가

```bash
cat hello >> world
```

`world`의 기존 내용을 유지하면서 끝에 `hello`의 내용을 덧붙인다. 대상이 없으면 생성한다.

### `<` — 파일을 표준 입력으로 사용

```bash
grep test < world
```

`world`의 내용을 입력으로 받아 `test`가 포함된 행을 찾는다.

### `|` — 프로그램 사이 연결

```bash
ls -l | grep hello
```

왼쪽 명령의 표준 출력을 오른쪽 명령의 표준 입력으로 연결한다. 긴 파일 목록에서 원하는 행만 추리는 식으로 작은 명령을 조합할 수 있다.

## 5. 사용자·그룹과 권한

### 사용자와 그룹

각 사용자는 이름과 UID를, 그룹은 이름과 GID를 가진다. 접근 제어는 계정의 ID와 소속 그룹을 자원의 소유자·소유 그룹 및 권한과 비교해 이루어진다.

- `/etc/passwd`: 사용자 이름, UID, 기본 GID, 홈 경로, 로그인 셸 등의 계정 정보.
- `/etc/group`: 그룹 이름, GID, 명시된 추가 구성원 목록 등의 정보.
- `root:x:0:0:root:/root:/bin/bash`: 강의의 root 계정 예. UID 0은 관리자 계정이다.
- `user:x:1000:1000:user,,,:/home/user:/bin/bash`: 일반 계정 예.
- `adm:x:4:syslog,user`: 그룹 정보 예.

```bash
cat /etc/passwd
cat /etc/group
```

### `ls -l`에서 권한 읽기

```text
drwxrwxr-x 2 user user 4096 ... dir
-rwxrw-r-- 1 user user   13 ... world
```

첫 열의 첫 문자는 종류다: `d`는 디렉터리, `-`는 일반 파일, `l`은 심볼릭 링크다. 뒤의 9문자는 소유자, 소유 그룹, 기타 사용자 순서로 3개씩 읽는다.

- `r`: 읽기. 파일의 내용 읽기, 디렉터리의 이름 목록 조회.
- `w`: 쓰기. 파일 내용 수정, 디렉터리 안에 항목 생성·삭제·이름 변경.
- `x`: 파일 실행, 디렉터리 탐색·통과.
- `-`: 해당 권한 없음.

`world`의 `rwx rw- r--`는 소유자 읽기·쓰기·실행, 그룹 읽기·쓰기, 기타 읽기만 허용한다. 소유자와 그룹명이 둘 다 `user`여도 **사용자와 그룹은 서로 다른 개념**이다.

숫자 권한은 `r=4`, `w=2`, `x=1`을 더한다. `rwx=7`, `rw-=6`, `r--=4`이므로 `rwx rw- r--`는 `764`이다.

> 보충·정정: 각 3비트를 값으로 바꾸는 계산과 달리 `chmod 764`의 전체 숫자 모드는 **8진수 표기**다. 또한 파일 자체의 쓰기 권한만으로 삭제 가능 여부가 결정되는 것은 아니다. 삭제에는 상위 디렉터리 권한과 sticky bit 등도 관여한다. [GNU 숫자 모드](https://www.gnu.org/s/coreutils/manual/html_node/Numeric-Modes.html), [권한 구조](https://www.gnu.org/s/coreutils/manual/html_node/Mode-Structure.html).

### `chmod` — 접근 권한 변경

일반적으로 파일 소유자나 적절한 관리자 권한을 가진 프로세스가 바꿀 수 있다.

```bash
chmod 764 hello
chmod g+x hello
chmod g-wx hello
```

첫 명령은 전체 권한을 지정한다. 둘째는 그룹 실행 권한만 추가한다. 셋째는 그룹 쓰기·실행을 제거한다. `u`는 소유자, `g`는 그룹, `o`는 기타 사용자이며, `+`는 추가, `-`는 제거다.

### `chown`, `chgrp` — 소유 정보 변경

```bash
sudo chown root hello
# 일반적인 소유자와 그룹 동시 지정 형식
sudo chown root:root hello
```

강의에서는 `hello`가 root 소유가 되고 일반 사용자에게 쓰기 권한이 없어 `echo "hello" > hello`가 `Permission denied`로 실패한다. 소유 그룹만 변경할 때는 `chgrp`를 사용한다.

> 보충·정정: 파일 소유자라고 해서 임의의 다른 사용자에게 소유권을 넘길 수 있는 것은 아니다. 리눅스의 소유자 변경에는 관리자 권한이 필요하고, 일반 소유자의 그룹 변경도 소속 그룹 등 제약이 있다. 원문은 `사용자.그룹` 형식을 소개하지만 새 명령은 이식성이 좋은 `사용자:그룹`을 권장한다. [GNU chown](https://www.gnu.org/s/coreutils/manual/html_node/chown-invocation.html).

### 특수 권한

1. **setuid**: 실행 파일의 소유자에 맞춰 프로세스의 유효 UID가 설정된다. 강의의 `/bin/passwd`는 root 소유와 setuid를 통해 일반 사용자가 필요한 비밀번호 변경 작업을 수행하는 예다.
2. **setgid**: 실행 파일의 소유 그룹에 맞춰 유효 GID가 설정된다.
3. **sticky bit**: 공유 디렉터리에서 비관리자가 다른 사용자의 파일을 임의로 삭제·이름 변경하지 못하도록 제한한다. 파일 소유자, 디렉터리 소유자, 적절한 관리자 권한은 구별한다.

표시 위치:

- setuid: 소유자의 실행 자리 `s`, 실행 비트가 없으면 `S`.
- setgid: 그룹의 실행 자리 `s`, 실행 비트가 없으면 `S`.
- sticky: 기타 사용자의 실행 자리 `t`, 실행 비트가 없으면 `T`.

숫자 모드의 맨 앞 특수 자리에는 setuid 4, setgid 2, sticky 1을 합산한다.

```bash
# 개념 확인용으로 직접 만든 실습 파일에만 적용
chmod 4755 world
chmod u+s world
chmod g+s world
chmod o+t lab_dir
```

`4755`는 setuid와 `rwx r-x r-x`다. **원문 설명의 4755와 터미널 예시의 4775는 다르다.** `4775`는 그룹에도 쓰기를 허용해 `-rwsrwxr-x`가 된다. sticky bit의 실질적인 삭제 제한을 실습하려면 일반 파일 `world`가 아니라 디렉터리에 적용한다. 특수 비트를 붙였다고 어떤 파일이나 스크립트가 무조건 권한 상승 실행되는 것은 아니며 파일 종류·시스템 정책에 따라 다르다.

<a id="directories"></a>
## 6. 주요 디렉터리

```bash
ls -l /
```

리눅스의 최상위 경로는 `/`이다. 강의에 나온 주요 위치와 역할은 다음과 같다.

- `/bin`: 일반 사용자가 쓰는 기본 명령과 실행 프로그램.
- `/boot`: 부팅에 필요한 파일.
- `/dev`: 디바이스 드라이버를 거쳐 장치에 접근하는 장치 파일.
- `/etc`: 시스템과 서비스 설정.
- `/home`: 일반 사용자의 홈 디렉터리들. 예: `/home/dream`.
- `/lib`: 프로그램과 시스템에 필요한 라이브러리, 기본 실행 파일의 동적 라이브러리 등.
- `/opt`: 추가 소프트웨어 패키지의 설치 영역.
- `/proc`: 커널·프로세스 정보를 파일 인터페이스로 제공하는 가상 파일시스템.
- `/root`: root 계정의 홈. 최상위 `/`와는 다르다.
- `/sbin`: 주로 시스템 관리에 쓰는 기본 프로그램. 위치만으로 실행 권한이 결정되는 것은 아니다.
- `/tmp`: 임시 파일. 정리 정책에 따라 삭제될 수 있으므로 영구 보관 용도로 쓰지 않는다.
- `/usr`: 사용자 프로그램, 문서, 라이브러리, 헤더 등.
- `/var`: 실행 중 변하는 데이터. `/var/log`는 로그 저장의 대표 예다.

강의의 루트 목록에는 `/media`, `/mnt`, `/run`, `/sys`, `/srv`, `/snap`, `/lost+found`, `swapfile` 등도 보이지만 개별 설명의 중심은 위 13개 경로다. `bin -> usr/bin`, `sbin -> usr/sbin`, `lib -> usr/lib`처럼 링크로 연결된 모습도 확인한다. 출력 날짜·크기·폴더 존재 여부까지 외울 필요는 없다.
