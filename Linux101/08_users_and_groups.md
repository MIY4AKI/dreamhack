## 1. 다중 사용자와 계정 정보

리눅스는 여러 사용자가 한 시스템의 자원을 함께 사용할 수 있도록 사용자와 그룹을 제공합니다. 파일의 소유자, 소유 그룹, 권한은 inode에 기록됩니다.

- **사용자(user)**: 계정이며 UID로 식별합니다.
- **그룹(group)**: 공통된 자원 접근 권한을 관리하기 위한 사용자 집합이며 GID로 식별합니다.
- 한 사용자는 기본 그룹 외에 여러 보조 그룹에 속할 수 있습니다.
- **root**: 전통적인 Unix의 최고 관리자 계정, UID 0입니다. 시스템 설정과 계정 관리처럼 일반 사용자에게 허용되지 않는 작업을 수행할 수 있습니다.
- `sudo`는 정책이 허용한 다른 사용자의 권한으로 명령을 실행합니다. 사용자를 지정하지 않으면 보통 root입니다.

사용자 ID와 그룹 ID는 파일 권한을 이해하는 기초이며, 이후 namespace나 cgroup 같은 심화 주제를 학습할 때도 중요합니다. 두 심화 주제 자체를 이 강의에서 자세히 다루는 것은 아닙니다.

## 2. passwd·shadow·group·gshadow

### /etc/passwd — 사용자 기본 정보

~~~text
이름:암호필드:UID:GID:추가정보:홈디렉터리:로그인셸
~~~

- 이름: 계정 이름.
- 암호 필드: 보통 `x`이며 실제 비밀번호 해시는 `/etc/shadow`에 있다는 표시.
- UID: 사용자 번호.
- GID: 기본 그룹 번호.
- 추가 정보: 설명 등의 정보.
- 홈 디렉터리: 계정의 홈 경로.
- 로그인 셸: 로그인했을 때 사용할 셸 경로.

~~~bash
cat /etc/passwd
~~~

### /etc/shadow — 비밀번호 해시와 사용 기간

일반 사용자에게 공개하면 안 되는 인증 관련 정보입니다. 강의는 관리자 권한으로 `sudo cat /etc/shadow`를 읽는 예시를 보여주지만, **자신의 실제 파일 내용이나 해시는 공유하지 않습니다.** 저장된 것은 보통 평문 비밀번호가 아니라 해시 값입니다.

표준 필드 순서:

~~~text
이름:해시:최종변경일:최소사용일:최대사용일:경고일수:비활성유예일수:계정만료일:예약
~~~

- 해시: 알고리즘에 따라 `$id$salt$hash` 등의 형식. `id`는 방식, `salt`는 해시에 사용하는 부가 값, `hash`는 결과입니다.
- `!`, `*` 등 유효한 해시가 아닌 값은 해당 Unix 비밀번호로 로그인할 수 없다는 뜻입니다. 다른 인증 수단까지 반드시 차단한 것은 아닙니다.
- 최종 변경일: 1970-01-01부터 지난 **일수**. 0이면 다음 로그인 때 비밀번호 변경 요구.
- 최소 사용일: 다시 변경하기 전에 기다릴 최소 일수. 0이면 제한 없음.
- 최대 사용일: 비밀번호를 변경해야 하는 최대 기간. 강의의 `99999`는 매우 긴 기간으로 쓰는 예시이지 문자 그대로 무한이라는 특수 값은 아닙니다.
- 경고 일수: 만료 전에 경고할 기간.
- 비활성 유예 일수: 비밀번호 만료 후 계정 사용이 차단되기까지의 유예 기간.
- 계정 만료일: 계정 자체의 만료 날짜를 1970-01-01부터 지난 일수로 표현.
- 마지막 필드: 예약.

> **강의 필드표 보충:** 비밀번호 만료 후 유예 기간과 계정 만료 날짜를 구분해야 합니다. 날짜 필드는 Unix timestamp의 초가 아니라 일수입니다. 비밀번호 만료와 계정 만료도 서로 다른 개념입니다. [shadow-utils shadow 매뉴얼](https://man7.org/linux/man-pages/man5/shadow.5.html)

### /etc/group — 그룹 정보

~~~text
이름:암호필드:GID:멤버목록
~~~

- `x`: 그룹 암호 관련 정보를 `/etc/gshadow`에 보관하는 표시.
- 멤버 목록: 쉼표로 구분된 사용자 목록.
- 사용자의 기본 그룹은 `/etc/passwd`의 GID로도 결정되므로 `/etc/group`의 멤버 칸만 보고 모든 소속 그룹을 판단하지 않습니다.

~~~bash
cat /etc/group
~~~

### /etc/gshadow — 그룹의 보호된 정보

~~~text
이름:암호필드:관리자목록:멤버목록
~~~

강의는 관리자 권한으로 `sudo cat /etc/gshadow`를 확인하는 예시를 보여줍니다. 그룹 비밀번호와 관리자·멤버 정보 등을 관리합니다. `*` 같은 값은 어떤 정상 비밀번호 해시에도 대응되지 않습니다. 실제 보호된 파일 내용을 노트나 공개 게시물에 복사하지 않습니다.

## 3. 파일 권한과 특수 비트

### u / g / o와 r / w / x

권한 주체는 세 가지입니다.

- `u`: 파일 소유자(user).
- `g`: 소유 그룹(group).
- `o`: 나머지 사용자(other).

각 주체마다 세 비트가 있습니다.

- `r`: 읽기, 값 4 = 이진수 `100`.
- `w`: 쓰기, 값 2 = 이진수 `010`.
- `x`: 실행, 값 1 = 이진수 `001`.

세 비트는 독립적으로 조합하며, 주체당 0~7의 값을 만듭니다. 예를 들어 `r-x`는 4+1=5, `rwx`는 4+2+1=7입니다. 권한의 합은 비트플래그를 OR로 묶는 것과 같습니다.

`-rwxr-x-w-`를 읽으면 맨 앞 `-`는 일반 파일, 그 뒤는 소유자 `rwx`, 그룹 `r-x`, 기타 `-w-`입니다. 각각 `7`, `5`, `2`가 됩니다. 일반 권한에는 총 9비트가 있습니다.

### 파일과 디렉터리에서의 차이

보충하면 같은 `rwx`라도 디렉터리에서는 의미가 달라집니다.

- 일반 파일의 r/w/x: 내용 읽기 / 내용 변경 / 실행.
- 디렉터리의 r/w/x: 항목 목록 읽기 / 항목 생성·삭제 등의 변경 / 경로 탐색·통과.
- 파일을 지울 수 있는지는 파일의 쓰기 비트만으로 결정하지 않습니다. **상위 디렉터리의 쓰기·탐색 권한**과 sticky bit 등의 조건이 중요합니다.

### setuid / setgid / sticky bit

숫자 권한 맨 앞 자리에 추가되는 특수 비트:

- **setuid = 4**: 지원되는 실행 파일을 실행할 때 파일 소유자 기준의 유효 UID를 사용하게 합니다.
- **setgid = 2**: 실행 파일에서는 소유 그룹 기준의 유효 GID. 디렉터리에서는 새로 만든 항목이 그 디렉터리의 그룹을 상속하는 데에도 사용됩니다.
- **sticky bit = 1**: 디렉터리 안의 항목을 삭제·이름 변경할 수 있는 주체를 파일 소유자, 디렉터리 소유자, 권한 있는 프로세스 등으로 제한합니다.

`s`는 사용자/그룹 실행 비트 위치, `t`는 기타 실행 비트 위치에 표시됩니다. 실행 비트가 없는데 특수 비트만 있으면 `S`, `T`처럼 대문자로 표시될 수 있습니다.

> 강의는 sticky 디렉터리의 삭제 주체를 root와 파일 소유자로 설명합니다. **디렉터리 소유자**도 포함한다는 점을 보충합니다. setgid의 디렉터리 의미도 실행 파일과 구별합니다. [Linux inode의 파일 모드 설명](https://man7.org/linux/man-pages/man7/inode.7.html)

## 4. 사용자 생성·수정·삭제

### useradd / adduser

형태: `useradd [옵션] 계정이름`. 계정 생성에는 관리자 권한이 필요합니다.

~~~bash
sudo useradd test
cat /etc/passwd | grep 'test'
sudo adduser test2
~~~

- `useradd`는 기본적인 계정 생성 명령.
- Ubuntu/Debian의 `adduser`는 비밀번호와 추가 정보를 질문하면서 여러 설정을 편리하게 수행하는 도구.
- 홈 디렉터리 생성 여부는 명령 옵션과 배포판 기본 설정에 따라 다릅니다. 원문 실습에서는 `useradd test`로 홈이 자동 생성되지 않는 상황을 다룹니다.
- 테스트 계정 이름이 이미 존재하면 새 계정을 중복 생성하지 않습니다.

### usermod / passwd

형태: `usermod [옵션] 계정이름`. 강의의 옵션 목록을 정확한 기능으로 정리합니다.

- `-p 해시`: 이미 해시된 비밀번호 값 설정. 평문 비밀번호를 주는 옵션이 아닙니다.
- `-d 경로`: 홈 경로 변경.
- `-u UID`: UID 변경.
- `-g 그룹`: 기본 그룹 변경.
- `-c 설명`: 추가 정보 변경.
- `-s 셸경로`: 로그인 셸 변경.
- `-m`: `-d`와 함께 기존 홈 내용을 새 경로로 이동.
- `-f 일수`: 비밀번호 만료 후 비활성 유예 기간.
- `-e YYYY-MM-DD`: 계정 만료 날짜.
- `-l 새이름`: 계정 이름 변경.
- `-L`: 비밀번호 잠금.
- `-U`: 비밀번호 잠금 해제.

강의의 UID 변경 예시는 `sudo usermod -u 23456 test` 후 `/etc/passwd`에서 test의 UID가 1001에서 23456으로 바뀌는 모습을 확인하는 것입니다. UID 변경은 기존 파일 소유권 등에 영향을 주므로 실제 계정에 무작정 적용하지 않습니다.

`passwd`는 비밀번호를 바꾸는 명령입니다. 일반 사용자는 보통 자기 비밀번호, 관리자는 다른 사용자의 비밀번호도 바꿀 수 있습니다.

~~~bash
sudo passwd test
~~~

> **옵션 혼동 주의:** 강의의 설명처럼 `passwd`와 `usermod`의 옵션을 그대로 서로 바꾸어 쓸 수 있는 것은 아닙니다. 비밀번호는 대화형 `passwd`로 변경하고, `usermod -p`에 평문을 넣거나 명령줄에 비밀 값을 노출하지 않습니다. `-L`은 비밀번호 인증을 잠그는 것이며 모든 인증 수단의 계정 접근 차단과 같지 않습니다. [usermod](https://man7.org/linux/man-pages/man8/usermod.8.html), [passwd](https://man7.org/linux/man-pages/man1/passwd.1.html)

### userdel / deluser

형태: `userdel [옵션] 계정이름`.

- `-f`: 강제 삭제. 계정·파일 관계에 문제가 생길 수 있으므로 주의.
- `-r`: 홈 디렉터리와 메일 스풀 등도 제거.
- Ubuntu/Debian에서는 `deluser`도 계정 제거용으로 사용할 수 있습니다.

강의 예시의 test 같은 **실습용 계정**만 정리합니다. `-r`은 자료 삭제까지 포함하므로 실제 계정에는 적용하지 않습니다. 계정을 지워도 다른 위치에 있는 모든 소유 파일을 자동으로 정리한다는 뜻은 아닙니다.

## 5. 그룹 생성·수정·멤버 관리·삭제

### groupadd / addgroup

형태: `groupadd [옵션] 그룹이름`. `-g GID`로 번호를 지정할 수 있습니다.

~~~bash
sudo groupadd test
cat /etc/group
~~~

Ubuntu/Debian에서는 `sudo addgroup 그룹이름`으로도 편리하게 생성할 수 있습니다. 강의는 `/etc/group`에 새 그룹이 추가된 모습을 확인합니다.

### groupmod

형태: `groupmod [옵션] 기존그룹이름`.

- `-n 새이름`: 그룹 이름 변경.
- `-g 새GID`: 그룹 번호 변경.

변경 후 `/etc/group`에서 정보를 확인합니다. 그룹 번호 변경도 기존 파일의 소유 그룹과 관계되므로 테스트 환경에서만 다룹니다.

### gpasswd

형태: `gpasswd [옵션] 그룹이름`. 그룹 관리자·멤버·비밀번호 정보를 관리합니다. 옵션 없이 그룹 이름만 주면 그룹 비밀번호를 설정합니다.

- `-r`: **그룹 비밀번호 제거**.
- `-R`: 그룹 비밀번호를 잠가 비회원의 그룹 사용을 제한.
- `-a 사용자`: 멤버 추가.
- `-A 사용자목록`: 그룹 관리자 목록 설정.
- `-d 사용자`: 멤버 삭제.
- `-M 사용자목록`: 멤버 목록을 지정한 목록으로 교체. 기존 멤버에 덧붙이는 옵션이 아닙니다.

~~~bash
sudo gpasswd -a user test
sudo gpasswd -d user test
~~~

> **강의 옵션표 정정:** `gpasswd -r`은 비밀번호 설정이 아니라 제거입니다. `-R`도 모든 기존 멤버의 접근을 일괄 금지한다는 의미로 단정하지 않습니다. root뿐 아니라 지정된 그룹 관리자에게 허용되는 작업도 있습니다. [shadow-utils gpasswd 매뉴얼](https://man7.org/linux/man-pages/man1/gpasswd.1.html)

### groupdel / delgroup

형태: `groupdel [옵션] 그룹이름`. `-f`는 강제 제거 옵션입니다. Ubuntu/Debian의 `delgroup`도 그룹 제거에 사용합니다. 강의는 제거 후 `/etc/group`에서 항목이 사라진 것을 확인합니다.

삭제 대상이 누군가의 기본 그룹이거나 실제 파일 접근에 쓰이는 그룹인지 확인해야 합니다. 실습용 그룹만 정리합니다.

## 6. 파일 소유자·그룹·권한 변경

### 실습 준비

원문은 이미 test 그룹이 있는 상황에서 test 사용자를 다시 생성합니다. 그룹을 중복 생성하지 않도록 `-g test`로 기존 기본 그룹을 명시합니다. 이후 `test_dir`와 `test_file`을 만듭니다.

~~~bash
sudo useradd -g test test
mkdir test_dir
touch test_file
ls -al
~~~

이것은 앞 실습에서 테스트 계정을 제거하고 테스트 그룹은 남아 있다는 **특정 상태의 예시**입니다. 계정이 이미 있다면 첫 줄을 재실행하지 않습니다.

### chgrp — 그룹 변경

형태: `chgrp [옵션] 그룹 파일/디렉터리`.

~~~bash
sudo chgrp test test_file
ls -al
~~~

파일의 소유 그룹이 test로 바뀝니다. 일반 사용자는 보통 자신이 소유한 파일을 자신의 소속 그룹으로만 바꿀 수 있습니다. 원문은 현재 사용자가 test 그룹에 없어서 sudo를 사용하는 예시입니다.

### chown — 소유자·그룹 변경

형태: `chown [옵션] 소유자:그룹 파일/디렉터리`.

~~~bash
sudo chown test:test test_dir
ls -al
~~~

test_dir의 소유자와 그룹을 모두 test로 바꿉니다. 소유자를 바꾸는 작업은 일반적으로 관리자 권한이 필요하며 단순히 “그 사용자와 같은 그룹이면 다른 사용자로 chown할 수 있다”는 뜻이 아닙니다.

### chmod — 권한 변경

형태: `chmod [옵션] 권한 파일/디렉터리`.

chgrp/chown/chmod에서 강의가 다루는 공통 옵션:

- `-c`: 실제로 변경된 항목의 처리 정보 표시.
- `-f`: 대부분의 오류 메시지 억제. 권한 검사를 통과시키는 기능은 아님.
- `-v`: 처리 정보를 자세히 표시.

**숫자 모드**는 `[특수][소유자][그룹][기타]` 순서의 8진수 숫자입니다.

강의 예제 `4752`를 해석하면:

- 4: setuid.
- 7: 소유자 rwx = 4+2+1.
- 5: 그룹 r-x = 4+1.
- 2: 기타 -w- = 2.

~~~bash
chmod 4752 test_file
ls -al
~~~

일반 파일의 표시로는 `-rwsr-x-w-`에 해당합니다. 특수 비트가 있다고 빈 텍스트 파일이 자동으로 실행 가능한 유효한 프로그램이 되는 것은 아닙니다. 관리자 소유 실행 파일에 특수 권한을 임의로 추가하지 않습니다.

**문자 모드**는 `주체 + 또는 - 또는 = 권한` 형태입니다.

~~~bash
chmod g+w test_file
chmod o-w test_file
~~~

- `u`, `g`, `o`: 소유자·그룹·기타. `a`는 모두.
- `+`: 추가, `-`: 제거, `=`: 지정한 조합으로 설정.
- `r`, `w`, `x`, `s`, `t`: 일반·특수 권한.
- 주체를 생략하면 모두를 대상으로 하지만 **umask에 따른 제한**을 받습니다. 강의의 “생략하면 모든 객체” 설명에는 이 조건이 있습니다. [GNU chmod 매뉴얼](https://man7.org/linux/man-pages/man1/chmod.1.html)

## 7. su와 sudo

### su — 다른 사용자로 전환

형태: `su [옵션] 사용자`. 사용자 이름을 생략하면 root입니다.

- `-c 명령`: 대상 사용자 권한으로 명령을 실행.
- `-` 또는 `-l`: 로그인 셸 방식으로 환경을 구성.
- `-s 셸`: 실행할 셸 지정.

강의의 테스트 계정에 비밀번호를 설정한 뒤 전환하는 흐름:

~~~bash
sudo passwd test
su test
~~~

일반적인 su는 대상 사용자의 인증을 요구합니다. `su test`는 로그인 셸 환경을 새로 구성하는 `su - test`와 다릅니다. 기존 작업 디렉터리 등이 유지되는 모습을 비교합니다. 다만 일부 HOME·SHELL 등의 값은 su의 규칙과 설정에 따라 변경되므로 “모든 환경 변수가 그대로”라고 단정하지 않습니다.

로그인 방식인 `su - test`는 대상의 홈으로 이동하고 그 사용자의 로그인 환경을 구성합니다. 원문처럼 useradd로 홈이 생성되지 않았던 상황에서는 먼저 홈을 올바르게 만들어야 합니다.

앞에서 `su test`로 들어갔다면 관찰을 마친 뒤 **`exit`로 원래 sudo 권한이 있는 계정에 복귀**합니다. 새 test 계정은 통상 sudo 권한이 없으므로 그 안에서 홈 준비용 sudo 명령을 실행하지 않습니다.

~~~bash
id
pwd
exit
id
~~~

`exit`는 현재 열린 su 셸 한 단계만 닫습니다. 셸을 여러 번 중첩했다면 필요한 단계만큼 복귀하고 `id`로 현재 계정을 확인합니다. 원래 계정에 처음부터 있는 경우에는 이 exit 단계를 실행하지 않습니다.

그 뒤 **원래의 sudo 가능한 계정에서**, 자신의 실습 VM에 test 홈이 없음을 확인한 경우 다음처럼 준비하고 로그인합니다.

~~~bash
sudo mkdir /home/test
sudo chown test:test /home/test
su - test
~~~

이미 경로가 있으면 소유권과 내용을 확인하고, 실제 다른 계정의 경로를 덮어쓰거나 변경하지 않습니다. 로그인 환경 비교가 끝나면 `exit`로 다시 원래 계정에 복귀합니다.

### sudo — 다른 사용자 권한으로 명령 실행

형태: `sudo [옵션] 명령`. 기본 대상은 보통 root이며, 허용 여부는 sudo 정책에 따라 결정됩니다.

- `-b`: 명령을 백그라운드에서 실행.
- `-C fd`: 지정한 번호 이상의 fd를 닫도록 요청. sudo 정책이 허용해야 하는 옵션.
- `-e`: 실행 명령 대신 파일을 지정하는 편집 모드.
- `-g 그룹/GID`: 실행 그룹 지정.
- `-u 사용자/UID`: 실행 사용자 지정.
- `-s`: 대상 권한으로 셸 실행.
- `-i`: 대상의 로그인 셸 실행.

예를 들어 `sudo -s`나 `sudo -i`로 관리자 권한의 셸을 열 수 있지만, 긴 시간 관리자 셸을 유지하기보다 필요한 명령의 범위를 확인해서 사용합니다.

강의는 일반 계정의 `cat /etc/shadow`가 권한 오류를 내고 `sudo cat /etc/shadow`는 읽을 수 있는 차이를 보여줍니다. 실제 인증 파일 내용을 공유하는 실습은 아닙니다.

## 8. sudo와 리다이렉션, tee

`sudo`는 지정한 **명령**의 실행 권한을 바꿉니다. `>`를 처리하는 현재 셸이나 파이프 뒤의 다른 명령까지 모두 root가 되는 것은 아닙니다.

따라서 root만 쓸 수 있는 실습 파일에 다음처럼 쓰면 실패할 수 있습니다.

~~~bash
sudo echo 'hello' > root_owned_test_file
~~~

여기서 파일을 여는 주체는 sudo의 echo가 아니라 기존 권한의 셸이기 때문입니다.

**tee**는 stdin을 받아 stdout과 지정한 파일에 함께 씁니다. 파일을 여는 tee에 sudo를 적용하는 방식으로 원문이 문제를 해결합니다.

~~~bash
echo 'hello' | sudo tee root_owned_test_file
~~~

위 파일 이름은 설명용이며 실제 시스템 설정 파일 경로가 아닙니다. 파일을 새로 쓰거나 덮어쓸 수 있으므로 자신의 VM에 만든 테스트 파일에서만 비교합니다. 파이프의 각 명령은 별개의 권한으로 실행된다는 점이 핵심입니다.
