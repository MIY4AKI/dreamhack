## 1. Network Lab

출처: [Lab: Linux - Network](https://learn.dreamhack.io/labs/ace97439-dcb1-409c-84e3-31f281cf21c9)

`nc`(Netcat)는 TCP/UDP 연결에서 데이터를 읽고 쓸 수 있는 도구다. 서버에 접속하는 역할과 연결을 기다리는 역할을 모두 수행할 수 있다.

### 과제 1. 접속

- 제공 환경의 HOST `localhost`, PORT **17374**에 접속한다.
- 프로그램이 출력하는 결과를 관찰하는 과제다.
- 답은 실제 서버 출력이며 임의의 문자열로 대신할 수 없다.

```bash
# 해당 Dreamhack Lab 안에서 실행하는 예시
nc localhost 17374
```

`localhost`는 현재 실행 환경 자신을 가리킨다. 사용자 Windows PC에서 이 명령을 실행한다고 Dreamhack의 Lab 서버에 연결되는 것은 아니다.

### 과제 2. 호스팅

- PORT **13575**에서 연결을 기다린다.
- Lab의 외부 프로그램이 연결해 메시지를 보내므로 그 결과를 확인한다.
- 안내는 `-l`(listen)과 포트 지정 옵션의 활용을 권한다.

```bash
# 구현에 맞는 형식을 nc -h / man nc로 확인
nc -l 13575
# 일부 구현에서 사용하는 형식: nc -l -p 13575
```

포트는 이 Lab이 요구한 값이다. 실제 운영 호스트에 새 서비스를 공개하는 안내가 아니다. 강의의 ‘IP를 임의로 변경할 수 없다’는 설명은 **제공된 실습 환경의 주소를 사용하라**는 맥락으로 이해한다. 일반적으로 네트워크 인터페이스의 IP는 권한·환경에 따라 설정 가능한 값이다.

Netcat은 구현마다 옵션과 `-l`/`-p`의 결합 규칙이 다르다. 강의 표를 모든 구현의 공통 규칙으로 외우지 않는다. [OpenBSD nc 매뉴얼](https://man.openbsd.org/nc), [네트워크 강의 노트](02_network.md).

## 3. 방화벽 기초 개념 퀴즈 — 7문항

출처: [방화벽 기초 개념](https://learn.dreamhack.io/quiz/131)

7문항과 선택지를 모두 읽었다. 사이트에서 선택하거나 ‘확인’을 눌러 제출하지는 않았다. 문항의 학습 포인트와 선택지에서 구별해야 하는 개념을 요약한다.

### Q1. 방화벽은 무엇을 하는가?

미리 정한 규칙으로 드나드는 **통신을 허용하거나 차단**하는 것이 핵심이다. 파일 암호화, CPU 사용률 조절, 이미 감염된 악성코드 제거는 방화벽의 정의를 대신하지 않는다.

### Q2. 실제 패킷 처리 결정은 누가 하는가?

커널의 **netfilter**가 패킷 처리 경로에서 결정을 적용한다. Bash 셸, 웹 브라우저, `iptables` 명령 자체가 커널을 대신해 모든 패킷을 직접 판정하는 것은 아니다. 명령 도구와 실제 처리 계층을 구별한다.

### Q3. nft의 위치와 특징은?

`nft`는 **nf_tables를 설정하는 현대적 도구**다. 강의에서 `inet` family를 사용하면 IPv4·IPv6를 함께 다룰 수 있다. 커널 없이 혼자 차단하는 프로그램, 속도 측정 도구, iptables보다 오래된 도구로 이해하면 안 된다. 어떤 family의 테이블을 쓰는지는 여전히 중요하다.

### Q4. 강의 환경의 iptables는 어떻게 동작하는가?

**iptables-nft 호환 구현**이 명령을 nf_tables 규칙으로 번역한다. 이 경우 nft와 완전히 독립적인 커널 기능이 아니다. iptables를 쓴다고 nft가 자동 삭제되는 것도 아니며, iptables가 IPv6 전용인 것도 아니다.

이 설명은 강의의 현재 Ubuntu 기본 환경을 전제로 한다. legacy backend와 다른 배포판·버전까지 항상 같은 구성이란 뜻은 아니므로 실제 시스템의 `iptables --version` 등으로 backend를 확인한다.

### Q5. 체인의 기본 정책을 drop으로 정하면?

앞선 규칙으로 허용되지 않고 **해당 체인의 끝까지 도달한 패킷을 버린다**. 명시적 허용 규칙은 여전히 의미가 있다. 기본 정책 변경은 모든 규칙 삭제나 모든 패킷에 거부 응답을 보내는 것과 다르다. 들어오는 통신을 설명할 때도 어느 체인에 적용한 정책인지 함께 본다.

### Q6. drop과 reject의 차이는?

- **drop**: 응답 없이 버린다.
- **reject**: 거부 응답을 돌려준다.

둘 다 차단 동작이다. drop이 허용이라는 뜻도 아니고, TCP와 UDP 전용 동작으로 서로 나뉘는 것도 아니며, 완전히 같은 결과를 주는 것도 아니다.

### Q7. ufw는 어느 계층의 도구인가?

강의 환경에서는 **ufw → iptables-nft → nf_tables**의 경로로 규칙이 반영된다. ufw는 사용하기 편한 설정 도구이지 다른 방화벽 계층과 무관한 별도 커널은 아니다. ufw를 사용한다고 nft를 자동 비활성화하지 않으며, iptables보다 항상 더 세밀한 제어를 제공하는 도구도 아니다.

복습용 관계도:

```text
사용자 설정 도구                  커널
nft ────────────────────────→ nf_tables / netfilter
iptables-nft ───────────────→ nf_tables / netfilter
ufw → iptables-nft ─────────→ nf_tables / netfilter
```

이 관계는 퀴즈의 환경을 나타낸다. 서로 다른 설정 도구로 동시에 규칙을 변경할 때는 현재 전체 규칙과 backend를 확인한다.

## 4. 실습 전 안전 체크

- 방화벽 변경은 원격 SSH 접속을 끊을 수 있다. 콘솔 접근·복구 방법을 준비한다.
- 규칙 삭제(`iptables -F` 등)와 기본 정책 초기화는 같은 일이 아니다.
- 기존 연결, 루프백, 관리용 SSH 허용 규칙과 기본 정책의 순서를 점검한다.
- `iptables`와 `ip6tables`, nft family 및 IPv4·IPv6 적용 범위를 구별한다.
- 재부팅 후 유지 방법은 별도 설정이 필요할 수 있다.
- Docker 공개 포트는 일반 INPUT 규칙만으로 보호된다고 가정하지 않는다.
- Lab의 주소와 포트만 대상으로 삼고 다른 사용자·실제 운영 시스템의 접근 제어를 바꾸지 않는다.
