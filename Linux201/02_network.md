## 1. 네트워크와 프로토콜

네트워크는 둘 이상의 컴퓨터가 통신하는 데 필요한 연결·장비·규칙 등을 통칭한다. 강의는 Net(그물)과 Work(일)의 합성어로 소개한다. 네트워크의 구조는 상황과 목적에 따라 달라진다.

사용자가 LAN이나 Wi-Fi에 연결해 브라우저에서 검색하면, 애플리케이션과 운영체제가 요청 전송 및 응답 수신을 처리한다. 사용자는 전기 신호나 패킷의 세부 구조를 직접 조작하지 않아도 인터넷 서비스를 이용할 수 있다.

통신 규약을 **프로토콜(protocol)**이라고 한다. 계층 모델은 통신의 각 역할을 나누어 이해하는 방법이다. 같은 장치 안에서는 인접한 계층의 기능을 사용하고, 상대 장치의 대응 계층과는 정해진 프로토콜에 맞추어 통신한다.

- 송신 방향으로 아래 계층을 거치면 해당 계층의 헤더 등이 붙는다: **캡슐화**.
- 수신 방향으로 위 계층에 전달하면 해당 계층의 헤더 등을 해석·제거한다: **역캡슐화**.
- 현대의 많은 네트워크 프로그램은 TCP/IP 프로토콜 모음을 이용한다.

## 2. OSI 7계층과 TCP/IP

강의는 이 부분을 완전히 암기하기보다 역할과 큰 흐름을 먼저 이해하라고 안내한다. 계층별 설명은 역할을 나눈 모델이며, 실제 기능이 항상 특정 하드웨어 한 곳에서만 구현되는 것은 아니다.

### 7. 응용 계층 — Application

사용자 애플리케이션에 네트워크 서비스를 제공한다. 보내려는 데이터를 서비스의 프로토콜 형식으로 만든다. 예: HTTP.

### 6. 표현 계층 — Presentation

송수신자가 이해할 수 있는 데이터 형식을 맞춘다. 강의는 문자 코드(ASCII/EBCDIC), 이미지 형식(JPG/PNG)의 차이를 예로 든다. 암호화·압축도 이 역할로 설명한다.

### 5. 세션 계층 — Session

애플리케이션 사이의 연결 상태인 **세션**을 유지·동기화하고, 연결을 생성·종료하거나 오류에서 복구하는 역할을 설명한다. 강의에서는 응용·표현·세션 역할을 애플리케이션 영역으로 묶는다.

### 4. 전송 계층 — Transport

송신자와 수신자 사이의 데이터 전달을 다룬다. 포트 정보 등을 포함하는 **세그먼트(segment)**를 만들고, 프로토콜에 따라 오류 검출·복구·흐름 제어를 수행한다.

- 대표 예: TCP, UDP.
- 모든 전송 프로토콜이 신뢰성이나 재전송을 보장하는 것은 아니다. UDP에 TCP의 보장을 그대로 적용하면 안 된다.
- 강의는 주로 운영체제가 처리하는 역할로 설명한다.

### 3. 네트워크 계층 — Network / Internet

IP 주소 등 논리적 주소를 포함하는 **패킷(packet)**을 만들고, 네트워크 사이에서 목적지로 보내는 경로를 선택한다. 라우터는 이 정보를 이용해 패킷을 전달한다.

### 2. 데이터 링크 계층 — Data Link

직접 연결된 링크에서 데이터를 전달한다. 상위 계층의 데이터에 MAC 주소 등 링크 정보를 붙인 **프레임(frame)**을 다룬다. 링크 기술에 따라 오류 검출이나 재전송 기능이 있을 수 있다. 강의는 스위치를 대표 장비로 소개한다.

MAC(Media Access Control) 주소는 링크상의 인터페이스를 식별하는 주소다. 강의는 기기별 고유 주소로 설명하지만, 주소를 변경하거나 가상 인터페이스에서 생성할 수도 있으므로 절대 불변의 신원 인증 수단은 아니다.

### 1. 물리 계층 — Physical

0과 1에 대응하는 전기·광·무선 신호를 실제 매체로 전달한다. 강의의 케이블 예시에서는 전기 신호로 설명하고, 허브를 대표 장비로 소개한다. 데이터 단위는 **비트(bit)**다.

### 그림의 모델 대응

- OSI 응용·표현·세션 → TCP/IP **Application** → 데이터.
- OSI 전송 → TCP/IP **Transport** → 세그먼트.
- OSI 네트워크 → TCP/IP **Internet** → 패킷.
- OSI 데이터 링크·물리 → TCP/IP **Network Interface** → 프레임과 비트.

강의 도식에 표시된 예시도 함께 기억할 수 있다.

- 응용: HTTP 외에 Modbus, SEP2, DNP3, IEC 61850, CIM, ICCP, BACnet, OpenADR, GOOSE.
- 표현: 압축과 암호화 관련 프로토콜.
- 세션 영역: NFS, SQL, SMB, RPC, P2P tunneling, SCP, SDP, SIP, H.323.
- 전송: TCP, UDP.
- 네트워크 영역: IPv4/IPv6, ARP, IGMP, ICMP.
- 링크: Ethernet.
- 물리 매체·규격: RS-232, UTP(CAT 5/6), DSL, 광섬유.

> 도식은 이해를 위한 개략적인 분류다. 실제 프로토콜은 여러 역할에 걸칠 수 있고, 특히 ARP처럼 모델마다 위치를 다르게 설명하는 경우도 있다. 이름들의 완전한 암기가 이 강의의 목표는 아니다.

## 3. 인터페이스와 ifconfig

**네트워크 인터페이스**는 장치가 통신하는 물리적 또는 가상의 연결 지점이다. 물리적인 NIC(Network Interface Card)는 LAN/Wi-Fi 신호와 디지털 데이터를 연결한다. VM이나 컨테이너 환경에서는 가상 NIC·브리지 같은 인터페이스도 생긴다.

`ifconfig`는 interface configuration에서 유래한 명령이다. 강의는 `net-tools` 패키지를 설치해 사용한다.

```bash
sudo apt install net-tools
ifconfig
```

인수 없이 실행하면 활성 인터페이스들의 정보가 나온다. 강의 화면의 `br-a755978236e8:`처럼 콜론 앞의 문자열이 인터페이스 이름이다. 이름은 환경마다 달라진다.

### 출력 항목

- `flags`: 인터페이스의 상태 플래그.
- `mtu`: 최대 전송 단위(Maximum Transmission Unit).
- `inet`: 할당된 IPv4 주소.
- `netmask`: IPv4 서브넷 마스크. IP 주소와 비트 AND 연산하면 네트워크 주소를 구할 수 있다.
- `broadcast`: 브로드캐스트 주소.
- `ether`: MAC 주소.
- `RX packets/bytes/...`: 수신 패킷·바이트 및 관련 통계.
- `TX packets/bytes/...`: 송신 패킷·바이트 및 관련 통계.

강의의 활성화·비활성화 문법은 다음과 같다. 인터페이스 상태 변경에는 보통 관리자 권한이 필요하다.

```bash
sudo ifconfig <인터페이스 이름> up
sudo ifconfig <인터페이스 이름> down
```

> 연결에 사용 중인 인터페이스를 내리면 인터넷이나 원격 접속이 끊길 수 있다. 모든 출력 값을 암기하기보다, 이름·주소·상태·송수신 통계를 어디에서 확인하는지 익힌다.

## 4. nc: TCP/UDP 연결

`nc`(netcat)는 TCP/UDP 네트워크 연결을 통해 데이터를 읽고 쓰는 도구다. 많은 Dreamhack 포너블 문제에서 서비스에 연결할 때 사용한다.

```bash
nc [옵션] <주소> <포트>
```

- 기본 사용: 다른 서버에 연결하는 클라이언트.
- `-l` 사용: 들어오는 연결을 기다리는 listen 모드, 즉 서버 역할.

### 강의의 옵션 목록

강의 표에는 아래 항목이 모두 등장한다. 다만 **모든 nc 구현에서 동일하게 작동하는 공통 옵션 목록이 아니다**.

- `-p <포트>`: 로컬 포트 지정.
- `-s <주소>`: 로컬 주소 지정.
- `-n`: 이름 해석 없이 숫자 주소·포트를 사용.
- `-u`: UDP 사용.
- `-l`: listen 모드.
- `-v`: 자세한 연결 정보 출력.
- `-d`: 강의에서는 백그라운드 모드로 설명한다.
- `-e <프로그램>`: 연결 후 프로그램 실행. 강의는 기본 `nc`에서 비활성화될 수 있고 `ncat` 등의 별도 구현을 언급한다.
- `-o <파일>`: 강의에서는 통신 데이터 저장으로 설명한다.
- `-c`: 강의에서는 LF(`\n`) 대신 CRLF(`\r\n`)를 쓰는 옵션으로 설명한다.

> **보충/정정 — 구현을 먼저 확인**  
> OpenBSD nc의 `-d`는 표준 입력을 읽지 않는 옵션이며 프로세스를 자동으로 백그라운드화한다는 뜻이 아니다. `-c`, `-o`도 구현·버전에 따라 TLS 관련 의미 등으로 다르다. Ubuntu의 설치된 `nc -h`와 `man nc`, `ncat`이면 `ncat --help`를 확인한다. 특히 `-e`는 네트워크로 프로그램을 직접 실행시키므로 공개 환경에서 무심코 사용하면 위험하다. [OpenBSD nc 공식 매뉴얼](https://man.openbsd.org/nc)

### 로컬 연결 실습

강의의 설치 예시는 다음과 같다.

```bash
sudo apt install netcat
```

배포판에 따라 `netcat`이 가상 패키지이거나 구현 선택이 필요할 수 있다. 강의 실습과 다른 메시지가 나오면 제공되는 구현을 확인한다.

터미널 두 개에서 아래 명령을 각각 실행하는 흐름이다.

```bash
# 터미널 1: 강의에서 사용한 listen 문법
nc -lvp 12345

# 터미널 2: 위 서비스에 연결
nc localhost 12345
```

클라이언트에서 문자열을 입력하면 서버 쪽에 같은 문자열이 출력되는 화면을 보여 준다. `localhost`는 자기 컴퓨터를 가리킨다. listen 문법은 구현에 따라 `nc -lv 12345` 등으로 달라질 수 있다. 일반적인 nc 연결은 SSH 같은 암호화된 원격 셸 연결과 다르다.

## 5. ssh: 안전한 원격 셸

SSH(Secure Shell)는 암호화되지 않은 원격 접속 방식인 TELNET의 한계를 보완하기 위해 등장한 프로토콜이다. 원격 시스템의 셸을 암호화된 연결로 사용할 수 있다.

- 기본 포트: TCP **22**.
- 강의는 0~1023의 well-known port 범위와 22번의 용도를 소개한다.
- 강의는 디피-헬만(Diffie-Hellman) 키 교환을 소개한다. 실제 SSH가 사용하는 키 교환 알고리즘은 서버·클라이언트의 설정과 협상 결과에 따라 달라질 수 있다.

```bash
ssh [옵션] <사용자>@<서버> [원격 명령]
ssh -p 22 id@host
```

원격 명령을 지정하면 접속한 시스템에서 해당 명령을 실행한다.

### 강의에서 다루는 옵션

- `-p <포트>`: SSH 서버 포트. 생략하면 일반적으로 22.
- `-v`: 접속 과정의 자세한 정보.
- `-i <개인 키 경로>`: 사용할 인증 개인 키 지정.
- `-X`: X11 포워딩을 요청해 원격 GUI 애플리케이션을 사용할 수 있도록 한다.
- `-C`: 통신 데이터 압축 요청.
- `-L`: 로컬 포트 포워딩.
- `-R`: 원격 포트 포워딩.

### 보충/정정 — 포트 포워딩의 방향

강의 표의 “로컬 주소/원격 포트” 표현은 혼동하기 쉬우므로 아래처럼 읽는다.

```bash
# 클라이언트의 local_port에서 받은 연결을
# SSH 서버 쪽에서 host:host_port로 전달
ssh -L <local_port>:<host>:<host_port> <사용자>@<SSH 서버>

# SSH 서버의 remote_port에서 받은 연결을
# SSH 클라이언트 쪽에서 host:host_port로 전달
ssh -R <remote_port>:<host>:<host_port> <사용자>@<SSH 서버>
```

`-L`은 클라이언트 쪽에서 대기하고, `-R`은 서버 쪽에서 대기한다. 대기 주소나 외부 공개 여부는 옵션과 서버 설정에 영향을 받는다. 서버의 `GatewayPorts` 설정 등도 관련된다. [OpenSSH 공식 매뉴얼](https://man.openbsd.org/ssh)

## 6. wget: 파일 다운로드

`wget`은 web get에서 유래한 파일 다운로드 도구다. 강의는 HTTP, HTTPS, FTP를 사용하는 URL에서 파일을 받는 기능을 소개한다.

```bash
wget [옵션] <URL>
```

### 옵션

- `-O <파일명>`: 저장할 파일 이름 지정. 대문자 O다.
- `--limit-rate=N`: 다운로드 속도 제한.
- `-b`: 백그라운드 다운로드.
- `-d`: 디버그 정보 출력.
- `--reject=<확장자 목록>`: 특정 확장자를 제외하는 필터.
- `-r`: 링크를 재귀적으로 탐색해 다운로드.

### 강의 화면의 예시

```bash
wget https://google.com
cat index.html
```

화면에서는 요청에 `301 Moved Permanently`가 반환되어 `https://www.google.com/`으로 이동하고, 이후 `200 OK` 응답을 받아 `index.html`로 저장한다. `cat`으로 저장된 HTML 내용을 확인한다. 실제 응답·파일 크기·주소는 실행 시점에 따라 달라진다.

> `-r`은 많은 링크와 파일을 가져올 수 있으므로 대상 사이트의 규칙과 범위를 확인한다. 받은 파일을 실행하는 것과 내용을 다운로드하는 것은 별개의 행동이다.

## 7. curl: URL로 데이터 송수신

`curl`은 URL을 통해 데이터를 보내고 받는 도구다. 강의는 client URL에서 유래한 이름으로 설명하며 HTTP, HTTPS, FTP, TELNET 등 여러 프로토콜 지원을 소개한다. 지원되는 실제 프로토콜은 설치된 빌드에 따라 달라질 수 있다.

```bash
curl [옵션] <URL>
```

### 옵션

- `-k`: HTTPS 인증서 검증을 생략한다. 연결 상대를 검증하지 않게 되므로 평소에는 사용하지 않는다.
- `-i`: 응답 **헤더와 본문**을 함께 출력한다.
- `-L`: 리다이렉트 응답의 다음 URL을 따라간다.
- `-d <데이터>`: HTTP 요청에 데이터를 보낸다. 일반적인 사용에서는 POST 요청이 된다.
- `-o <파일명>`: 응답 데이터를 파일로 저장한다. 소문자 o다.
- `-X <메서드>`: GET, POST, DELETE 등 요청 메서드 문자열을 지정한다.
- `-A <이름>`: User-Agent 값을 지정한다.
- `-H <헤더>`: 요청 헤더를 추가·지정한다.
- `-u <사용자>:<암호>`: 인증용 사용자와 암호를 지정한다. 실제 비밀번호를 명령에 직접 넣으면 셸 기록 등에 남을 수 있다.

> **보충/정정**: 강의의 `-i` 설명은 “HTTP 헤더만 출력”이라고 되어 있지만, `-i`는 헤더를 **본문과 함께** 표시한다. `-I`(대문자 I)는 HTTP HEAD 요청으로 헤더를 요청한다. [curl 공식 HTTP 사용 문서](https://curl.se/docs/httpscripting.html)

### 강의의 GET 요청

```bash
curl -X GET https://google.com
```

강의 화면에는 `301 Moved` 응답이 나온다. 브라우저도 리다이렉트를 받지만 보통 자동으로 다음 주소를 따라간다. curl에서 이를 원하면 `-L`을 사용한다.

```bash
# 보충: 리다이렉트를 따라가는 예
curl -L https://google.com
```

`wget`의 기본 다운로드 흐름과 `curl`의 기본 출력·리다이렉트 처리 차이를 비교하면 명령을 선택하기 쉽다.

## 8. Lab과 복습 체크

강의 마지막의 [네트워크 Lab](https://learn.dreamhack.io/labs/ace97439-dcb1-409c-84e3-31f281cf21c9)은 배운 명령을 브라우저 실습 환경에서 연습하도록 안내한다. 실제 Lab 단계와 접근 범위는 이 폴더의 실습 정리에서 별도로 다룬다. 이 노트 작성 중에는 실습 터미널에 명령을 입력하지 않았다.

- [ ] 계층·프로토콜·캡슐화의 의미를 설명한다.
- [ ] 데이터 → 세그먼트 → 패킷 → 프레임 → 비트의 흐름을 안다.
- [ ] IP 주소, MAC 주소, 포트가 구분하는 대상을 구별한다.
- [ ] `ifconfig`에서 인터페이스 이름·주소·수신/송신 통계를 찾는다.
- [ ] nc의 클라이언트와 listen 모드를 구분하고 구현별 옵션을 확인한다.
- [ ] SSH 기본 포트, 개인 키, X11, 압축, 포워딩 방향을 이해한다.
- [ ] wget으로 파일을 받고 curl로 요청을 보내는 차이를 안다.
- [ ] `wget -O`와 `curl -o`, `curl -i`와 `curl -I`를 혼동하지 않는다.
- [ ] 인증서 검증 생략·인터페이스 비활성화·공개 listen의 위험을 이해한다.
